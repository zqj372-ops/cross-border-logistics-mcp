# Access Gateway 产品实施路线图

本路线图把“代码存在”与“产品可用”分开。当前目标是先完成企业接入和运营闭环，再选择一个低风险
T1 物流场景；未取得真实外部设施证据前，`production_eligible` 必须保持 `false`。

## 当前批次：P0 运营闭环

### 已进入实现

- 管理员只读运营概览；
- 租户、Client、Key 有效状态汇总；
- 24 小时五状态调用计数；
- 最多 20 条脱敏最近异常；
- ChatGPT Work、Codex、企业助手接入清单；
- SQLite/PostgreSQL 同合同投影；
- Access Console 生产门禁读回。

验收口径见 `docs/rfcs/2026-08-30-access-operations-overview-v1.md`。

## P0 后续批次

### 企业成员与角色

目标角色：Owner、Admin、Operator、Auditor。需要独立 RFC 决定邀请、离职停权、break-glass、
角色到 scope 的精确映射和审计保留期；不能把所有 Cloudflare 登录用户静默映射为平台管理员。

### Agent 接入自检

在不持久化 Key/JWT 的前提下完成：选择 Client → 生成无密钥配置 → 兑换短期 JWT → MCP initialize →
`tools/list` 精确读回 → 清除页面内存。兑换成功不能替代 MCP 目录读回。

### 外部设施生产门禁

- OCI Vault/KMS 或等价非导出 signer 与轮换演练；
- Secret Manager pepper 与历史版本读取；
- 托管 PostgreSQL 或经过批准的等价 HA/PITR 方案；
- 集中吊销、告警、负载、备份恢复、区域故障和回滚证据；
- Cloudflare Access 应用、MFA、真实管理员登录回执。

这些事项由部署环境完成；仓库只能提供 provider port、配置校验和失败闭合，不能自行声明已配置。

## P1：真实物流业务价值

第一项优先选择 T1 外部只读的运输跟踪与异常识别。它必须使用权威来源、短期凭证、egress
allowlist、超时、来源版本和 `manual_review|unavailable` 失败闭合。报价、关务、正式发送、订舱和
其他写操作继续保持关闭，直到各自合同、审批、幂等和写后读回通过独立门禁。

业务人工复核需要独立工作流：负责人、SLA、证据引用、评论、重新执行、关闭原因和全程审计。
Access Gateway 的最近异常列表不是业务复核任务系统。

## P2：可扩展与商业化

- Agent 引导式需求诊断、受控模板、沙箱、构建报告和发布候选；
- 已批准静态能力的配置中心、版本固定、弃用、灰度和回滚；
- 套餐、计量、配额、账单、SLA、状态页和客户支持；
- 多区域、数据驻留和企业合规材料。

第一版不实现远程任意代码安装、生产 hot-plug、通用写入口或插件市场。

## 完成定义

一个企业管理员在不使用命令行的情况下完成以下流程，P0 才算产品闭环：

1. 通过企业 SSO/MFA 登录；
2. 创建租户和调用方；
3. 精确选择允许工具并签发一次性 Key；
4. 安全保存并确认交付；
5. 连接一种 Agent 客户端并读回精确工具目录；
6. 查看调用量、五状态和最近异常；
7. 轮换/吊销 Key，并验证旧凭证立即失败；
8. 从审计引用追踪操作，且任何页面和日志都不出现完整凭证或客户原文。
