# 运营使用手册

[文档中心](../README.md) / 运营

**打开一票业务，依次完成：核对需求 → 套费用 → 出报价 → 接单 → 跟进。**

使用[运营后台](https://www.freightclaw.net/ops/)。账号按个人用户组和订单分工授权；收件邮箱只是通知地址，不等于系统权限。

## 人员与权限

| 用户组 | 可操作范围 |
| --- | --- |
| 客户 | 本人关联业务、对客报价、客户可见进度 |
| 业务员 | 本人受理的询价、报价、接单和费用维护 |
| 操作员 | 获分配的执行节点，不开放成本售价和费用模板 |
| 管理员 | 人员授权、系统设置；业务仍按订单授权 |

新账号默认为客户。管理员打开「人员与权限」，按姓名或登录邮箱查找，选择用户组并保存。对方需先正常登录一次。改回客户后，后台访问立即停止，历史业务保留。

已有平台运营兼容为业务员，已有节点参与人兼容为操作员；显式设置优先。通知邮箱不能代替账号授权，管理员不能自行降级。

## 找到要处理的业务

列表按业务阶段切换；「待我处理」只看本人待办。表格集中显示客户、SO / 柜号、航线、状态、待办和计划截止时间，点击右侧「查看」进入本票。

单号、航线、客户和「仅异常」筛选作用于已加载记录；需要继续查找时点击「加载更多业务」。「重置」清空这些条件，「刷新」重新读取当前阶段。

## 报价：海运费 + 其他费用

![费用来源示意](../assets/quote-sources.svg)

| 操作 | 要做的事 |
| --- | --- |
| 核对需求 | 查看航线、柜数、货物、服务和客户；资料不足先补齐 |
| 选择海运费 | 按航线、船公司、柜型选择记录；没有价格先维护 |
| 套用费用模板 | 选择其他费用组合，直接核对明细 |
| 修改本票 | 调整数量、成本、售价及服务范围，核对分币种合计 |
| 出报价 | 保存、核对、完成相应审核并发布；需要文件时导出 PDF |

海运费表是基础海运费的唯一维护来源。模板用于港杂、清关、拖车、派送等其他费用。历史模板中还有非零海运费时，先核对原金额、币种和计算关系，再处理；不能隐藏后继续计费，也不能直接删掉造成漏算。

海运费与费用模板不要求有效期，按更新时间判断是否需要复核。**正式报价仍有有效期**。更新价格用于新报价，不覆盖历史金额。金额显示最多两位小数，币种分别核对。

## 接单：确认服务，再开始执行

客户确认后，在该票业务核对委托并接单。补充 SO、柜号和本票对接人，按所选服务开始执行。不要另建重复业务单。

整柜到门与清提派的起始环节不同，只配置本票需要的节点，不为未购买的服务制造完成记录。

| 环节 | 跟进内容 |
| --- | --- |
| 订舱 / 放 SO | 订舱情况、SO、船期及文件 |
| 中国提货 / 装柜 | 提货、装柜与柜号 |
| 出口报关 | 报关资料及处理进度 |
| 补料 / 提单 | 补料、提单及确认记录 |
| 加拿大清关 | 清关资料、补件和清关进度 |
| 拆柜 / 仓储交接 | 到仓、拆柜与交接情况 |
| 派送 / 签收 / 还柜 | 预约、派送、签收及还柜记录 |

## 每次跟进只做三步

1. 打开节点，填写实际进度、时间和必要资料。
2. 选择「客户可见」或内部记录。对外文字写清发生了什么、下一步是什么。
3. 保存后检查记录与邮件状态；需要对接人通知时，核对收件人和可见字段。

全局节点设置用于新业务；在途订单在本票修改负责人和通知。不能只改全局设置后假定本票也已更新。

## 报关附件怎么发

在本票上传文件，选择要发送的附件，核对收件人、主题、正文和附件后发送。查看邮件记录确认结果。上传成功、邮件服务器接收、对方收到并打开附件是三件不同的事。

连接配置、内外部通知和财务提醒见[邮件设置](../runbooks/fcl-mail-settings.md)。

## 操作异常

| 情况 | 下一步 |
| --- | --- |
| 资料不完整 | 补缺项，保留已知数据 |
| 没有匹配海运费 | 维护或选择价格，不能以 0 代替 |
| 版本已变化 | 刷新记录，核对后重新编辑 |
| 权限不足 | 核对个人账号、负责人和节点授权 |
| 发送结果不明 | 先查邮件记录与收件箱，避免重复发送 |
| 待复核 / 来源不可用 | 核对来源或配置，不能手动改成成功 |
