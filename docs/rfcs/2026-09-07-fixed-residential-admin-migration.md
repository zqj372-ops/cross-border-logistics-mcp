# 固定私人地址后台功能移植

状态：按用户明确要求实施的原后台功能迁移细化。范围是 native business 管理合同与界面，不变更 Phase 1 MCP 工具、统一业务查询输入输出或渠道合同。

## 动机与来源

用户要求私人地址不设渠道，配置应方便好用，并明确以 `quote.freightclaw.net/admin` 的原始代码为移植依据。冻结来源为 canada-final-mile-auto-quote 提交 `e7d26d9711ea2183dacea9ab6016008f5ad64ff1` 的 PricingSettingsPage.tsx、CitySettingsPage.tsx、QuoteSettingsPage.tsx 和 zone_price_spreadsheet.py。原项目目录只读，不导入旧业务配置与凭证。

移植价格矩阵、分区筛选、城市邮编维护、分区启停与燃油覆盖、表格导入预览和费用核验。新后台保持同一企业固定始发信息，不复制多渠道控制器、旧账号体系、AI/邮件/企业微信管理或报价话术编辑器。后者属于不同功能边界，不影响本次固定派送计价配置。

## 合同与兼容

旧发布没有 extensions 字段，沿用已经明确保存的全局燃油和启用的分区价格。新增可选、严格验证的扩展：

```json
{"extensions":{"zone_controls_v1":[{"zone":1,"enabled":false,"fuel_percent":null}]}}
```

`zone_controls_v1` 每个分区最多一条。enabled=false 返回 manual_review / zone_disabled；燃油 null 明确使用本份已发布 fees.fuel_percent，十进制字符串覆盖该比例。未知字段、重复分区及不存在的分区拒绝发布。没有配置的价格仍不得外推，空价格不是零。MCP 原有查询合同不变，管理 Schema 纳入该明确扩展命名空间。旧 CLI 无法识别扩展时应失败闭合，使用同次构建 CLI。

网页和 CLI 使用相同的本地表格转换逻辑读取 CSV/XLSX/XLS，原文件不上传到旧服务。只解析首张工作表并显示表名；不接受公式作为价格。限定文件、行列及记录数。始发仓列存在时必须与当前固定始发仓一致，不猜仓、不跨仓合并。可预览新增/覆盖数量和错误行，再合并到编辑中的草稿。导入不是发布；CLI 预览输出可审阅的完整 save_input，通过既有 save / preview / publish 实施写入。全量导出包含明确选择的草稿或发布版本，不默认为当前有效价。

## 权限、迁移和回滚

保留现有人员会话、企业隔离、预览摘要、幂等、版本冲突和写后读回。导入预览/导出是现有 get 权限下的本地投影；没有新的万能写入口。保存使用现有 residential-rates/save。新扩展不需要数据库结构迁移。回退可重新发布无扩展的历史版本；不得用旧程序静默忽略新扩展并对外出价。

## 验证

覆盖矩阵/长表识别、重复/错误/跨仓/公式拒绝、空格与零价、草稿合并和原对象不变；分区禁用转复核、燃油覆盖金额、旧版本计算不变。浏览器验证批量预览确认、矩阵编辑、搜索、费用预览和移动端；CLI 验证读取文件、预览、保存与发布后网页/CLI 一致。正式业务数据和外部承运商验收独立进行。
