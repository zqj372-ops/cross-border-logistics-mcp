# 个人用户组

用户要求重新划分客户与运营。沿用个人身份、FCL HTTP/CLI、现有配置仓储和订单授权；不改 MCP 工具、企业数据归属或历史金额。

- 客户：默认组，只读本人关联业务和对客材料，可确认报价。
- 业务员：本人询价、报价和接单，订单/节点权限仍逐项校验。
- 操作员：仅获分配的执行节点，不开放成本、售价、费用模板及接单操作。
- 管理员：固定受理人为初始管理员，管理人员分组；管理权限不带来跨账号业务读取权限。
- 旧平台运营和已有节点分派仅作为兼容依据，页面标明来源。显式调整为客户后立即停止后台 API 访问，旧订单归属与节点记录不删除。
- 通知邮箱不等于账号，不通过邮箱猜测或创建授权。人员列表仅包含已登录核验的账号。

接口新增 group-self、group-list、group-save，使用既有 FCL 包络及 CLI 路由。旧接口不变；session 的 extensions.user_group_v1 提供分组提示，实际请求重新校验。

旧：{"personal_operator":true}。新：保留旧字段，增加 {"extensions":{"user_group_v1":{"group":"operations","can_manage":false}}}。

group-save 输入：{"user_id":"existing-sub","group":"customer","expected_version":0,"confirmed":true}；actor 仅来自会话。写入须管理员授权、幂等键、版本检查、事务审计和读回。固定管理员不可自行降级；其他账号仅分配客户、业务员或操作员。设置存于已有 native_configs，不建独立用户/订单权威表。

验证范围：客户、业务员、操作员、固定管理员、原节点参与人；跨账号数据、版本冲突、重放、撤权后的旧会话、配置读回。生产启用需核验现有人群及运行版本；不自动迁移企业关联、不删除记录。回退须保留权限配置，不能回到忽略显式撤权的旧后端。

## 本地验收记录

2026-09-29：相关网关、CLI 与控制台共 171 项测试通过；后续界面调整重跑控制台 124 项及登录导航 3 项通过。`npm run typecheck`、`npm run lint`、`npm run validate:schemas`、`npm run validate:agent-standards`、`npm run build`、`git diff --check` 通过。

Edge 在隔离 fixture 中完成管理员查找人员、改为操作员、保存读回、操作员入口、撤权后后台拒绝、返回客户中心及退出登录。真实本地 HTTP 验证业务员授权后可建本人询价，管理员不能读取该账号业务，操作员不能读取报价列表，撤回为客户后旧会话不能读取工作区。

仅本地测试，未提交、推送或部署；未更改正式账号用户组。

## 发布前复查

降为操作员后，历史受理人身份不再额外授予列表、节点管理或商业配置权限；仅保留实际节点分派或本票协调人权限。补充历史受理人撤权测试。CLI 新增三条用户组命令，发布版本为 0.022，安装包与页面一起更新。
