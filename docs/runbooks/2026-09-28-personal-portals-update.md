# 加拿大整柜到门与清提派：轻量版整合规划

2026-09-28 · 分批实施中，完成情况见第 9 节。

## 1. 首版只做一条流程

询价 → 报价 → 客户确认 → 运营接单 → 清关、提柜、派送 → 完成。

询价、报价、订单始终沿用同一票，不让客户重新填写订单，不复制一套订单主库。客户端与运营端独立入口，共用现有个人账号登录和业务服务。

两种服务共用表单和详情页，只改变需要填写的字段与实际服务节点：

- **中国到加拿大整柜到门**：按委托范围处理中国起运、海运、加拿大清关和派送。
- **加拿大清提派**：从加拿大港口/铁路场站开始，处理清关、提柜和派送；不要求选择基础海运费。
- 两者都明确是否包含返空、卸货及其他附加服务；不默认全部包含。

交付方式只加一个选择：**整柜直送一个地址**，或**拆柜后分送**，也可暂待确认。两种服务均可采用两种交付方式，不新增第三个业务系统。客户选择分送时才显示目的仓/地址、对应箱数或托盘数；询价阶段未知可补，不按零计算。

| 服务 | 报价组成 | 客户需补充的主要信息 |
| --- | --- | --- |
| 中国到加拿大整柜到门 | 所选基础海运费一次＋实际委托的其他费用 | 中国起运地、加拿大目的地、柜型柜数、货物、交付方式、预计时间 |
| 加拿大清提派 | 加拿大段费用方案＋未包含的本票附加费 | 加拿大港口/场站、目的地、柜型柜数、货物、交付方式、已知到达安排 |

表中费用组成描述的是服务范围，不将成本和售价混加。提单号、柜号、最终资料在产生或需要时补充，不作为所有询价的前置条件。

## 2. 页面只保留这些

| 端 | 入口 | 页面内容 |
| --- | --- | --- |
| 客户中心 `/customer/` | 我的业务 | 一张业务列表，右上角“发起询价”；筛选待我处理、进行中、已结束 |
| 客户中心 | 本票详情 | 报价、当前进度、对客流转记录与资料；顶部直接显示下一步按钮 |
| 运营后台 `/ops/` | 业务单 | 默认“待我处理”，可查看授权范围内全部业务；不另建工作台或统计大屏 |
| 运营后台 | 本票详情 | 需求摘要、报价费用、执行进度与流转记录；操作随当前阶段出现 |
| 运营后台 | 业务设置 | 海运费、费用模板、其他模块；复用现有编辑器 |

人员、邮件和账号安全放右上角设置菜单，只向有权限的人显示。客户与供应商名称、地址、联系方式放本票资料，复用已有资料能力，不新建 CRM。

列表只显示：编号、客户（仅运营端）、服务/线路、柜型柜数、当前进度、下一步；运营另显示负责人及下次跟进时间。每行直接打开该票；提供“今天要跟进、已逾期、全部授权业务”筛选，不新增独立待办系统。

### GUI 操作规则：按任务安排页面

详情只保留三个页签：**需求与报价、进度与记录、资料**。页头显示编号、进度和下一步；运营端另显示负责人和跟进时间。切换和刷新保留当前页签及输入；返回列表保留筛选和位置；邮件登录后回到对应业务。

| 操作场景 | 界面约定 |
| --- | --- |
| 下一步 | 每个阶段只突出一个主操作；不能操作时说明缺什么或在等谁。 |
| 填写 | 中文标签，标明必填；只显示相关字段。错误就地提示，保留输入。 |
| 费用 | 表格内增删改；金额右对齐，币种明确，最多两位小数。未保存时标明。 |
| 保存 | 保存与发布分开；提交时防重复，失败可重试；离开未保存页面时提醒。 |
| 对外操作 | 发布、确认、取消前核对内容和版本；普通编辑不反复弹确认。 |
| 异常 | 区分无记录和读取失败；邮件失败不要求重新下单。 |
| 键盘与手机 | 焦点清楚，可用键盘操作；手机单列，主要按钮至少 44px。 |

沿用蓝色和现有组件。正文 14–16px，边框轻、表格紧凑；删除重复标题、说明和装饰。宽表只在表格内滚动，费用可逐行编辑。

验收检查标签、键盘操作、对比度、窄屏和错误恢复。

## 3. 客户只需四类操作

1. **发起询价**：一页分“运输要求、货物与交付、联系方式”三个小段，根据服务和交付方式显示字段。联系姓名和有效邮箱用于受理；影响正式报价的缺项集中提醒，未知项允许留待补充。无需创建企业，也不强制提交前登录。
2. **补充资料或凭证**：只显示缺什么，保留已填内容，不重填整张表。查看私人内容前核验身份；资料或付款凭证提交后等待运营核对，不自动认定通过或到账。
3. **查看并确认报价/变更**：展示费用、范围、除外项目、有效期；一个按钮完成准确版本的确认，委托提交后显示“待运营接单”。后续新增费用、地址或范围变更仍在本票确认，也可填写修改意见。
4. **查看进度并反馈问题**：显示目前到哪一步、接下来做什么、是否需要客户处理；取消请求、签收异议和售后问题在原票提交，不另建询价。

确认委托不等于订舱成功。运营接单也不等于清关或场站放行。价格、地址或范围变化时，回到该票确认新内容，不覆盖原记录。

认领须验证本人身份及与该票的关系；仅知道业务编号或在表单填写某个邮箱不足以取得访问权。

页面只显示五个主阶段：询价中、待客户确认、待运营接单、执行中、已结束。已结束须写清“已完成/已取消/未受理”；待补资料、报价过期、异常单独提示。这是展示归类，不改掉后台已有细分状态与校验。

## 4. 运营在一页办完一票

### 报价

**选海运价（到门服务需要）及费用模板 → 修改本票费用 → 出报价。**

- 先按目的城市、直送/分送缩小模板列表，由运营选定。模板名称采用“多伦多 YYZ3/YYZ4”“温哥华混装分送”等业务叫法，不让客户理解产品编号和内部规则。适用条件不符时人工调整，不自动选择最低价。
- “方案”只是现有费用模板的业务名称，不新增产品、套餐或规则管理层。模板选择是快捷操作，没有匹配模板仍可在同一页录入本票费用。
- 选择后立刻展开全部费用，直接修改金额、增删本票费用；修改本票不会回写模板，重复选择同一模板不能重复追加收费。
- 运营表保留费用名称、成本单价、销售单价、数量/单位、币种、销售小计；来源放费用名旁的次要文字。客户表只显示费用、单价、数量/单位、币种、小计，不获得成本和利润。金额右对齐，不横向堆出多个工作区。
- 基础海运费只取所选海运费记录一次，费用模板仅含其他费用；缺少必需价格时提示补充，不能用零代替。
- 已确认的清提拆派组合价保留一条费用，所含服务明确列出，不猜测拆成各环节金额。包含的提柜、拆柜、清关等不再叠加同范围单项收费；范围不明或交叠时提示运营核对，确认前不发布正式报价。
- 同行销售价与采购成本分别记录。只有售价时成本标记待核对，不能填零制造毛利，也不能直接当采购价。超箱数、跨城、额外托盘、等待等条件先用简短说明＋人工增加本票费用，沿用已有计费能力，不建立条件树。
- 海运费表和费用模板没有有效期，保留更新时间；正式报价保留有效期。
- 金额最多显示两位小数，按币种汇总；历史金额与报价版本不被改写。
- “出报价”进入现有预览/审核及正式发布流程，不新增多级审批，也不跳过已有必要审核。
- 历史模板中无法确认归属的非零海运费明确标注待核对，不静默删除或重复叠加。

“需求与报价”页签由上到下：一行需求摘要、一张费用表、按币种汇总及主要操作。执行和跟进放“进度与记录”，文件放“资料”，不在报价表下继续堆叠。历史版本和完整原始资料按需展开。来源成本的可编辑性沿用既有规则，人工费用保留修改原因。

### 接单和执行

客户确认后，这一票自动进入运营待办。核对服务范围和承接条件后点击“接单”；不能承接时退回说明或拒绝，不反复要求客户再创建订单。

每票一个负责人，首版不要求逐节点指派；已有协作记录与权限继续保留。新公开询价沿用此前确认的固定受理人，分单才变更负责人。

执行区只列本票相关事项：例如起运安排、订舱、到港、清关、提柜、派送、签收、返空；选择拆柜分送时才出现拆柜和各目的地交付事项。运营更新已核实的事实、时间和凭证，调用现有对应动作，不开放任意修改订单状态的万能接口。首版人工录入即可完成流程，不依赖自动船期采集成功。

多柜在同一票内逐柜记录；分送在票内简表记录目的地和交付结果，不新建仓库库存系统。不同目的地可分别签收，空柜可在拆柜后先返还，不能强制等全部分送完成才返空。未发生的节点不用填写；委托范围全部完成且未决事项已处理才标记“已完成”。

### 流转记录：一条时间线看过去，一条待办看下一步

本票顶部固定显示“当前进度、负责人、现在等谁、下一步、下次跟进时间”，不要求逐节点设置岗位。资料待客户补充或供应商待反馈时，本票负责人仍负责跟进。

详情页的“进度与记录”按时间倒序显示，最近发生的在上面。默认看关键业务记录，运营可筛选“全部、内部跟进、客户可见”，历史记录逐批加载。

| 记录来源 | 自动记录的内容 |
| --- | --- |
| 询价与资料 | 谁提交或补充了什么、时间、资料版本及文件入口 |
| 报价与确认 | 报价版本、发布/修改原因、客户确认的准确版本及时间；内部金额仅向有权限的人员展示 |
| 接单与移交 | 谁接单、谁转给谁、交接说明、未完事项及当前负责人 |
| 执行 | 哪个柜/目的地发生了什么、实际时间、录入人及凭证；录入时间与实际发生时间分开 |
| 通知 | 对应业务事件下显示发送情况；失败留原因，不能把 SMTP 接受写成客户收到或同意 |

关键业务动作成功后自动留记录，不让运营另外抄写日志。网页、CLI、API 经同一业务服务产生记录；幂等重试不重复记同一动作。普通输入、刷新、未提交草稿不刷入业务时间线。报价版本、执行、通知记录按既有引用关联展示，不另建一套权威流水库。

客户只看到客户可见事件、正式报价和获授权文件；内部沟通、采购成本、毛利、供应商联系方式不返回客户接口。运营也只能查看授权业务及字段。时间线中的客户可见修改摘要和附件都要经过服务端过滤，不能只在页面隐藏。

### 跟进：只增加一条记录，不再填一套任务表

运营点击“添加跟进”，输入“本次情况”；需要继续处理时再填“下一步、下次跟进时间”。默认仅内部可见，不自动发邮件。普通跟进记录不能替代客户确认、报价变更、清关放行或签收等正式动作。

- 没有明确时间可留空，不自动生成虚假截止日期。已设置时间的未完待办进入“今天要跟进/已逾期”；物流最后免费日等实际业务截止与人工跟进时间分开标注。
- 客户提交资料后，“等待客户提交”转为“等待运营核对”，不得直接消失；核对通过才结束本次补料，退回则列明缺项。相关正式动作完成才解除对应待办；历史跟进说明保留。单纯收到邮件或手写“已完成”不能关闭有正式前置条件的任务。
- 更改负责人时一并展示未完事项，原负责人和新负责人及移交说明都留痕。明确分配完成前不让任务消失。
- “通知客户”使用已有相关模板，先预览收件人与正文再确认；普通内部备注不转成客户通知。未发送、已提交发信服务器、失败及人工确认收到分别显示。
- 更正错误以补充记录说明，不覆盖原来的已完成业务事实；实际状态回退、重开、取消继续走现有对应动作和原因校验。

首版只提供票内记录和列表跟进筛选，不新增聊天系统、自动读取邮箱、任意任务编排或多层催办升级。

### 首版必须补齐的业务条件

| 阶段 | 进入下一步的条件 | 不满足时如何处理 |
| --- | --- | --- |
| 受理询价 | 联系方式、服务和已知需求已保存；匿名客户须核验后查看私有内容 | 缺项保留待补，不猜测柜数、地址或价格；不重复建票 |
| 发布正式报价 | 需求已核对；价格、范围、币种、条件费用和正式报价有效期明确；已有必要审核通过 | 保持草稿；指出缺价、冲突或待核对来源，不按零元发布 |
| 客户委托 | 本人对仍有效的准确报价版本确认；约定条款可回看 | 报价过期或需求变化则重新报价；客户修改意见不是确认 |
| 运营接单 | 核对服务边界、货物属性、地址/卸货条件、价格和可承接安排；本票负责人已确定 | 暂待核对、要求补充或明确拒绝；不用勾选无证据的“全部完成”绕过 |
| 委派作业 | 本次执行方、作业范围、所需资料及适用的付款/放货条件明确；授权人员确认发出 | 缺项留待办；“已发出”不等于执行方已接受，不自动触发真实订舱/报关/支付 |
| 清关、提柜、派送 | 对应资料已核对，实际前置条件和安排已确认；凭据属于本柜/目的地 | 分别保留待确认及阻碍原因，不能从清关放行推导场站可提或已提柜 |
| 运输完成 | 委托范围内所有柜/目的地完成，签收和适用返空证据齐全 | 部分完成保持可见；未执行的范围不误标完成 |
| 费用和售后收尾 | 实际费用已核对，应收应付或外部账务记录可追踪；未决异常有负责人 | 运输完成可保留“费用待核对/待收款/售后处理中”，不倒改运输事实，也不清空剩余待办 |

这些条件复用已有专用动作和校验。只有对应阶段才显示相关字段，首版不增加通用工作流设计器。运输完成、费用结清和售后解决分别记录；第 3 节五个主阶段用于运输业务展示，不承担财务状态。

**资料清单。** 按委托范围列出本票必要资料，首版由运营核对，不把固定列表当成通用清关结论。询价只收基本需求；执行时再按需收发票、装箱资料、提单/到货资料、代理所需授权和派送资料等。每项记录名称、提供人、所涉柜/目的地、文件版本、状态（待提供/待核对/可用/需重交）、核对人及退回原因。上传、核对是两步；替换文件保留旧版本，引用旧文件的已完成记录不重写。原始资料、对客报价及内部凭据按对象权限分开返回；附件限制大小与类型、检查归属，文件名和客户正文按不可信输入处理。

**执行方确认。** 在对应节点复用联系人和事件记录，填写实际执行方、指令/委托版本、发送时间、接受或拒绝结果及证据。发出后等待回复进入负责人待办；可人工记录线下回复，注明核对人、时间和来源。换供应商保留原安排及取消/变更结果，未确认前不能显示“已安排”。联系人不自动获得后台账号或整票访问权，不新增供应商门户。

**关键期限。** 按实际适用范围保存提柜最后免费日、返空期限和预约窗口等已核实时间；标明适用柜号、来源、当地时区、核对人及更新时间。无来源时待核对，不按到港日推算。负责人设置提前跟进时间，复用今天/逾期筛选；期限修改保留前后值并刷新未完提醒。人工跟进时间不能冒充船公司或场站期限。

**追加费用与执行变更。** 本票费用表保留原已确认版本，新增行记录原因、金额、币种、计费依据/凭据、涉及范围及客户确认状态。已包含项目不重复收费；未知金额保持待核对。已事先约定的条件费用也须保留对应条款版本和实际依据，不一律认定需重新同意或一律认定已同意。需要客户确认时按既有报价/变更版本提交，客户拒绝后保留争议及处理安排，不自动继续执行受影响的额外服务。更改地址、柜数、服务、供应商或取消时明确影响范围；仅暂停受影响动作，不倒改其他已完成事实。客户端与运营同时修改时用版本冲突保护，不能后保存覆盖先保存。

**账款跟踪。** 首版只做票内费用跟踪：约定付款方式/时间、分币种应收应付、实际收付记录及凭证或外部账务引用、核对人和时间。应收与应付分别计算，不能互抵；部分收付和退款保留明细，余额来自已核对记录，不能凭上传凭证或勾选“已付”认定到账。客户仅看自己的应付及对客账单，不看采购成本、供应商应付或利润。付款条件是否阻断作业依本票已确认约定，不统一规定预付或月结；没有付款约定先核对，不擅自扣货。不接在线支付，不发起转账，不建设会计总账、税务开票或复杂核销系统。税费和代垫金额沿用已核验依据，不由系统推定。

**异常与售后。** 复用跟进记录标明异常类型、影响范围、当前负责人、下一步、可选约定时间、证据和结果。取消请求、取消被接受、作业实际停止分别留痕；已产生费用不能直接删除，退费记录须有依据。货损、短少、拒收、二次派送等仍挂原票，是否赔付及金额由有权人员核实，不自动判责。运输已完成后允许有权限的人继续费用及售后跟进；普通备注不能修改签收、返空或放行事实。

**中途接入与代录。** 清提派允许接手已经开船或到港的货物。接单记录接手时间、实际服务起点、已发生事项及证据；委托外的起运/海运节点标记不适用，不要求客户补走流程。运营代录时记录来源及本人操作身份，不冒充客户账号；未经客户核验与确认，不能自动认领或产生客户同意。重试沿用原幂等键；相似需求只提示核对，不自动合并不同订单。

## 5. 权限按个人，不做企业工作区

| 预设 | 能做什么 |
| --- | --- |
| 客户 | 本人询价/订单、对客报价、补资料和确认委托 |
| 运营 | 本人负责或明确分配的业务；被授权的模块维护 |
| 管理员 | 人员权限、分单和系统设置；业务数据仍按明确授权范围访问 |

首版可由同一个人兼任运营与管理员，不配置部门树。客户公开注册不能自行成为运营。

本人提交者、付款联系人、收货联系人、供应商联系人是业务关系，不等于系统角色。订单确认权默认属于已核验的委托客户；增加联系人不自动授予确认、报价或全票查看权。管理员分配本人账号的运营资格和可访问范围，维护模块的编辑/发布权限另行明确。当前已有个人报价工具资格不是新客户的运营授权依据；切换前核对已有账号与数据用途，保留旧个人自用资料的可追溯访问，不将其混入新客户订单或自动授予跨账号管理权。

模块权限使用现有能力，分别控制可编辑和可发布；不提供自定义权限规则编排。用户停用立即撤权，未完任务进入待分配。每次 API、附件下载、导出和 CLI 都检查个人权限及数据归属；收到邮件不代表获得订单权限。

企业名称、客户/供应商资料和报价抬头是业务信息，继续保留。历史企业数据先核实归属，不自动分给当前账号。

| 空柜返还 | 对应柜号、已核实返还时间及凭证入口 | 核对剩余委托事项；可在分送全部签收前发生 |
| 本票完成 | 委托范围已完成、文件入口及联系渠道 | 结束本票未完待办 |
| 异常、费用/范围变更、取消 | 说明实际影响与处理要求；变更需确认，取消需实际生效 | 对应处理、确认或取消任务 |

内部记录始终完整，但只有需要负责人行动或原计划变化时才发内部邮件，避免每条正常进度再重复抄送。首版仍由本票负责人跟进，需要移交时才通知新负责人。

### 正文如何随节点变化

客户主题统一为“【{{节点名称}}】{{业务编号}}”，报价主题另带版本。正文只保留本次变化、涉及范围/实际或预计时间、客户下一步和详情入口。

- **待接单**：您已确认第 {{报价版本}} 版报价并提交委托，当前待运营接单；此通知不代表订舱或提柜已经完成。
- **清关资料已提交**：本票清关资料已于 {{时间_含时区}} 提交 {{接收方类别}}，目前 {{已核实阶段}}。下一步：{{下一步}}。此通知不代表海关已经放行。
- **清关已放行**：本票 {{放行范围}} 的放行结果已核实。下一步核对场站及提柜条件，尚不表示货柜已提离。
- **已提柜**：本票 {{柜号摘要}} 已于 {{实际时间_含时区}} 提离 {{场站}}，下一步 {{下一步}}。
- **派送已预约**：{{目的地}} 已预约 {{预约窗口_含时区}} 派送。收货要求：{{必要收货要求}}。安排变化时请通过本票页面联系。
- **已签收**：{{目的地}} 已于 {{实际时间_含时区}} 签收，凭证见本票页面。{{剩余委托事项说明}}
- **已返空/已完成**：返空只陈述相应柜号的返还事实；只有全部委托完成才使用“本票服务已完成”，不由签收或返空单一动作推断。

以上文字共用已定义的正文类别，不新增一排需要用户配置的节点模板。无客户待办时写“暂无需您操作”；暂无实际时间时不能把预计时间写成已完成时间。未核实的金额、凭据和进度阻止生成相应成功通知。

- 匿名回执只核验并提供简短确认；详细地址、货物和报价仅提供给已核验且有业务访问关系的人。
- 客户确认提交后页面与邮件均显示“待运营接单”，同时提醒内部负责人；重复确认不重复发信。
- 普通保存、刷新和无变化的船期同步不发邮件；关键节点按服务预设，客户只收到与本票相关的变化。
- 同一保存操作同时完成多个柜或目的地的同类进度时，可合并为一封并逐项列明；每项原始事件仍保留，异常或需客户行动的内容不被合并隐藏。不为等其他柜更新而延迟发送当前重要通知。
- 默认客户收件人为已核验主联系人，收货联系人仅收到获授权目的地的派送/签收信息；供应商只收到经批准的作业资料，不收到客户售价、利润或完整内部记录。各受众使用独立邮件，不能整封互相抄送。
- 金额/范围改变必须绑定需确认的新版本。邮件链接只打开页面，点击链接本身不能确认委托、费用或取消。
- 没有客户待办时显示“暂无需您操作”，不强制截止日期。实际完成时间、金额和放行凭据不能编造。
- 邮件失败进入运营待办；同一事件去重，结果未知不自动重发，发送前取消已失效的通知。
- 已经发出的错误通知不能撤回时，业务更正另发明确的更正通知，并关联原事件；原记录不覆盖。发信记录保留事件、正文/模板版本、收件人、尝试及结果，敏感内容仅在获授权详情中读取，不进入通用日志。
- SMTP 接受、提供方投递证据和人工收件确认分开记录。首版不新增已读追踪。
- 清关委托、派车等供应商执行指令沿用获授权人员审阅后的操作，不混入默认自动提醒。

## 8. 实施顺序和完成标准

按一条完整业务路径交付，先本地贯通再进行发布验收：

1. 分离客户/运营入口，完成个人权限；在同一票打通公开询价、本人认领、报价、客户确认和运营接单。
2. 接入现有执行节点、关键邮件和个人模块设置；完成两种服务的 GUI 全流程。
3. 核对历史归属，在隔离副本演练迁移；之后分别记录发布、运行读回及真实邮件收件验收。此规划不表示当前已部署。

验收只抓实际结果：

- 两个客户账号数据不串用，普通客户不能进入运营管理；获授权个人无需企业即可维护指定模块。
- 一票无需重复录入；重复确认不重复建单；过期或已替换的报价不能确认。
- 基础海运费只计算一次，清提派不强制海运价；新报价使用新价格，历史报价保持原样。
- 组合价已含服务不重复加单项费；成本未知不显示虚假利润，重复套用不重复追加，修改本票不改变模板。
- 每票只展示相关节点，未核实的订舱、放行或签收不能标为成功；返空义务未完成不能误结案。
- 直送只填一个地址；分送可分目的地签收和先返空，仍能在同一票核对全部委托范围。
- 报价、确认、接单、移交及执行自动产生关联流转记录；来源版本、操作者、时区和文件可核对，重复请求不重复留痕。
- 客户时间线及附件无内部内容泄露；跟进到时可在列表找到，办结后退出未完筛选，移交后负责人及未完事项保持连续。
- 邮件正文、收件人和链接正确，失败可见且不重复发送；桌面与窄屏金额、表格、按钮可正常操作。
- 用本地合成数据分别走到门直送、清提派和拆柜分送：询价、报价、委托提交、接单、清关、提柜、派送、签收、返空、结案的适用节点都有对应流转记录及通知；内部与外部收件范围不串用。
- 业务保存和发件任务原子记录，重启后未发任务仍在；重复提交不重复发信，发送失败不回滚已成功的业务，撤回/换版后不继续发失效通知。生产发信及人工收件验收另行记录，不能以本地队列代替。
- 前段邮件单独验收：未核验询价仅最小回执、内部新询价到正确受理人、补资料通知可续接原表、正式发布才发报价、新版金额/币种/有效期/PDF 同版、修改意见提醒负责人、客户确认后双向通知且明确待接单。
- GUI 实际验收：分别以客户、运营账号完成主流程，使用鼠标及仅键盘操作；核对每步下一动作、字段错误、未保存提醒、重复点击和网络失败恢复。以没有开发者口头指引也能继续操作为目标，不能只凭截图判定流程可用。

**怎么操作**

1. 客户提交询价，在回执点击“在客户中心跟进”，使用询价邮箱登录并关联。已有询价可粘贴原查询链接关联。
2. 运营在 `/ops/` 核价、审核并导出 PDF，点击“发布报价并通知客户”。
3. 客户在 `/customer/` 核对明细、服务范围和有效期，点击“确认报价并提交委托”。
4. 运营在“进度与记录”点击“接单并开始执行”，按本票服务填写节点资料、完成交接；客户在同一业务页看进度。

**权限和数据**

- 运营角色来自服务端个人授权或固定受理人配置；节点参与人仅进入获分配的业务和节点。没有企业创建、绑定或切换步骤。
- 客户须同时证明原询价邮箱和查询凭证；只看本人对客报价与进度，不能读成本、利润和内部备注。退出/换账号清空界面缓存。
- 确认绑定指定报价版本；过期、换版、取消均不能确认。运营接单再次执行原报价、PDF 和来源校验。同票只建一份执行记录，重复操作不重复接单。
- 原 owner、企业关联及历史金额不动；没有归属证据的历史票不自动转给任何账号。未核对的生产历史数据尚未迁移。

**邮件**

询价回执 → 报价发布 → 委托提交 → 接单 → 节点完成/异常 → 完结，复用持久化队列。未验证询价只发通用回执；报价邮件含币种金额、正式有效期和客户入口，不含内部成本。节点内部/外部通知沿用已有正文及配置。页面草稿不发邮件；发送失败保留记录，结果未知先核实再重试。

本地测试使用合成 SMTP 接收器；没有发送真实邮件，也没有证明真实收件箱送达。
