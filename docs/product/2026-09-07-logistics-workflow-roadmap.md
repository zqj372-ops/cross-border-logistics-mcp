# FreightClaw 物流业务工作台与能力扩展规划

执行进度：[前后台询价受理第一阶段](2026-09-07-business-cases-delivery.md) 已有代码与本地验收；原生引擎、配置后台及后续扩展仍按本文规划推进，未宣称完成。

状态：产品规划，未实现或启用新增功能。依据用户已确认的“业务代码迁入、空白配置、新后台、保留账号与 Key”，纳入 OCR、报价导出、邮件订舱和 SO 识别。本文不是发送邮件、连接邮箱、订舱或扩大现有 Key 权限的操作授权。

## 一、产品定位与范围

FreightClaw 从“能力市场 + 单项查询”扩展为围绕一票业务的物流工作台。对外保留简单的海运询价、关税查询与开发者接入；内部提供资料、报价、订舱、SO、待办和配置管理。

本规划将 SO 暂按海运场景的订舱确认/装货指示类单据处理。具体字段、状态与确认依据要在实施时用实际船公司或货代样本确定，不能只按文件名中的 SO 判断单据类型或订舱结果。

主要用户：

- 货主/商家：提交需求、补资料、查询关税、获取获准的报价结果。
- 报价/操作人员：核对识别资料、计算和审核报价、准备订舱、核对 SO 与关键日期。
- 管理人员：维护规则、模板、供应商和连接，审核发布，处理失败和异常。
- 系统/Agent：调用已授权的窄功能，读取处理状态；不能从查询权限推导发送或订舱权限。

用户已明确不需要企业微信。首期不包括财务付款、正式报关、自动订舱决策、任意插件安装或通用拖拽流程设计器。

## 二、围绕同一票业务串联

```mermaid
flowchart LR
  A[上传文件 / 粘贴资料] --> B[识别字段]
  B --> C[人工核对需求单]
  C --> D[运费试算 / 关务查询]
  D --> E[报价审核与版本]
  E --> F[导出报价]
  F --> G[准备订舱草稿]
  G --> H[核对收件人正文附件]
  H --> I[授权发送]
  I --> J[等待供应商回复]
  J --> K[导入 SO 并识别]
  K --> L[核对差异与版本]
  L --> M[确认订舱结果 / 待办提醒]
```

这些环节可以单独进入：已有 SO 可以直接上传识别；已有报价可以直接录入引用后准备订舱；报价被拒绝或失效不能自动推进。平台内部使用统一业务编号关联资料，外部订舱号、报价号和提单号分别保存，不能混成一个编号。

一票业务初始是需求单，不默认代表订单已成立或舱位已确认。状态分开保存：需求核对状态、报价状态、邮件投递状态、订舱状态、SO 复核状态。用一条时间线展示这些对象的实际进度，不用一个“完成”覆盖所有步骤。

## 三、能力规划

| 模块 | 首期输入与输出 | 后台可配置 | 必须保留的边界 |
|---|---|---|---|
| 文件与 OCR | PDF/图片上传；先读取已有文本层，扫描件进入 OCR；返回原文、页码、位置及字段候选 | 支持类型、页数/大小限制、识别服务、语言、保留期与额度 | 原件只读；字段必须能定位到原文；识别到不等于确认 |
| 询价资料识别 | 文本、装箱单、商业发票等；提取件数、包装、尺寸、重量、体积、地址、货值及币种 | 文档分类、字段映射、单位校验、复核条件 | 单件/总计、净重/毛重、币种、否定服务条件要分开；冲突不能自动覆盖 |
| 报价与导出 | 已保存的报价版本；导出 PDF 客户报价单，按授权导出 Excel 费用明细 | 公司抬头/Logo、语言、条款、费用展示、有效期、编号和模板版本 | 草稿加水印；正式文件固定报价与模板版本；不在导出时重新计算价格 |
| 邮件订舱 | 经确认的订舱申请；生成邮件正文、主题和附件清单，确认后发送，关联后续回复 | 企业邮箱、供应商联系人、线路模板、签名、必填资料及发送权限 | 邮件发出不等于订舱确认；不从附件文字自动更改收件人或发送动作 |
| SO 识别与核对 | 上传/收到的 SO；提取候选字段、与申请对照、展示差异并确认新版本 | 供应商模板、字段别名、港口/柜型映射、日期与时区规则、复核项 | SO 的修订、取消、条件性确认必须保留；不得按置信度自动确认舱位 |
| 待办与通知 | 识别失败、资料缺失、待审核、待回邮、SO 差异及关键日期 | 负责人、提醒规则、站内提醒；邮件提醒另需授权配置 | 初期站内待办，不预先发送任何通知；时区不明不创建确定提醒 |

OCR 与 SO 识别共用文件、识别任务和字段证据基础设施，但使用不同业务提取模板。报价金额与税费仍由确定性引擎负责。模型可以抽取、追问、解释和写草稿，不能用 OCR 置信度或模型判断代替价格权威、税则来源或订舱确认。

## 四、SO 工作台细化

首期候选字段：供应商/船公司、订舱号、船名航次、起运港/目的港/中转港、柜型柜量、提柜或还柜信息、预计开航/到港日期、截港/截补料/截 VGM 时间及其时区、单据签发/修订日期和附加条件。具体字段是否存在及含义依实际样本确定；缺失不补猜。

页面采用“左侧原件，右侧字段与差异”布局，点击字段定位原文，保留未识别、待核对、已确认、与申请冲突四种业务字段状态。日期同时显示原始文字和规范化值；当地时间、UTC 与未知时区不能混用。

确认流程：

1. 选择或建议匹配业务单据，展示匹配依据；仅匹配置信度不足时由人员选择。
2. 检查订舱号、港口、柜型柜量、航次与关键日期；对照申请突出差异。
3. 必须确认属于本企业、本票业务及有效供应商回复；相同文件哈希可以提示重复，但不能单凭相同订舱号覆盖另一票业务。
4. SO 修订创建新版本，记录取代哪个旧版本和改了哪些字段；保留全部原件。
5. 经人员确认后生成或更新业务待办；已有提醒需要相应更新，并保留变更记录。

仅上传 SO 或提取到 booking number，不自动设置“订舱成功”。需要单据/回复确实表达确认且人员完成核对。取消文件不能被最新上传时间掩盖。

## 五、报价导出细化

现有 Portal 已有报价记录、审核、PDF 生成和下载适配代码。可复用其版本固定、来源复核和文件读回原则；这些现有实现不代表新内置引擎或正式业务全流程已经验证。原海运询价页面目前生成询价邮件并打开邮件应用，不是服务器邮件发送或订舱系统。

首期提供两类文件：

- **客户报价 PDF**：报价编号、收发货范围、货物摘要、服务范围、金额/币种、有效期、条款、公司信息；仅展示获准的客户价格。
- **内部费用 Excel**：分项、币种、计算依据、版本与复核状态；供应商成本、利润和内部备注按角色控制，不自动出现在客户文件里。

要求：多币种分别展示；没有明确汇率与日期不合成单一总价。正式报价过期或待审核时不导出无水印正式件。修改货物或价格后创建新报价版本，旧文件仍能读回当时快照。下载链接短期有效且校验访问权限；文件失败允许重建同一任务，不能生成重复业务记录。Excel 中用户提供的文本防止被当作公式执行。

模板从空白业务配置开始：可提供不生效的结构示例，但不能自动填入旧公司资料、收款信息、价格或客户条款。模板预览使用明确合成数据。

## 六、邮件订舱细化

第一版采用“准备草稿 → 人工核对 → 明确发送 → 跟踪回复”。首期可先支持手工上传回复和附件，再接入限定文件夹/时间范围的企业邮箱收信。具体邮箱服务商、API/SMTP/IMAP 等接入方式待邮箱条件核对，不提前绑定某一种产品或全邮箱扫描。

订舱草稿来自明确选择的需求、报价和附件版本；不自动把客户报价 PDF、供应商成本表或商业发票全部附上。人员选择供应商联系人，核对主题、正文、柜型柜量、港口、货物、预计日期、委托条件和附件清单后确认发送。收件人、正文或附件变化使之前的发送确认失效。

邮件状态至少分清：草稿、待发送确认、提交发送、服务商已接收、投递状态未知/已投递（仅有回执时）、退信、发送结果待核对。业务订舱状态另行记录：准备中、已提交申请、供应商要求补料、待确认、已确认、被拒绝、取消/修订待处理。

发送须绑定内容摘要、附件版本、收件人和幂等标识，持久保存发件任务与服务商 message ID。遇到“服务商可能已接收但本地超时”，先核对发件记录，不能盲目重发造成重复订舱。无法证实时保持待核对；系统不得宣称 exactly-once 邮件投递。

回复关联使用线程/消息头、订舱号和业务编号提供候选，正文中的任意链接或指令不能触发自动发送、下载未知地址或修改权限。收到可识别附件仅进入待复核队列，不自动确认订单。

## 七、前后台导航

前台首页继续突出海运询价、关税查询；能力市场展示模块是否已实现、已配置、可用或需要权限。新文件处理和订舱功能默认登录后使用，不自动继承关税访客额度。

**内部业务工作台**：

1. 工作概览：待核对资料、待审核报价、待回邮订舱、SO 差异和临近截止时间。
2. 业务单据：需求、货物、报价、邮件、SO 和时间线，围绕同一票业务切换。
3. 资料中心：原件、识别、核对、版本和业务归属。
4. 报价中心：试算、记录、审核、导出及历史文件。
5. 订舱中心：申请、邮件草稿、发送记录、回复及 SO。
6. 待办任务：负责人、原因、下一步、截止时间和处理记录。

**业务管理后台**：

- 基础资料：企业、渠道、仓库、供应商、联系人和数据字典。
- 规则与价格：分区、运价、附加费、计费规则和发布版本。
- 关务数据：官方数据导入、校验、审核和发布。
- 单据模板：报价 PDF/Excel、订舱邮件、SO 提取模板、语言和字段映射。
- 服务连接：OCR、AI、邮箱、Freightcom、文件存储的安全配置与测试。
- 权限与额度：上传、识别、成本查看、正式导出、发信、确认订舱分别授权；运营额度与计费分开。
- 发布与运行：草稿版本、连接状态、任务失败、重试、审计和可控回退。

管理员无需日常修改服务器环境变量来调业务规则；机密仍保存在服务端安全存储，通过后台配置而非以明文展示。空白初始化没有生效模板、供应商联系人、邮箱连接或默认通知接收人。

## 八、现在必须打好的共同基础

| 基础对象 | 用途 | 关键要求 |
|---|---|---|
| 企业与业务单据 | 把资料、报价、订舱、SO 归到同一票 | 所有读写校验企业和角色；关系有明确来源，不靠文件名 |
| 文件与文件版本 | 原件、生成件、预览和下载 | 不可变原件、内容哈希、文件类型校验、受控存储、保留/删除政策；扫描隔离后再处理 |
| 识别结果与字段证据 | 原文→候选值→确认值 | 原始文字、页码/位置、单位、提取器版本、确认人及时间；人工确认不覆盖原文 |
| 后台任务 | OCR、批量识别、导出、收发信等耗时操作 | 持久队列/任务表、有界重试、超时、取消、失败原因、重启恢复；发送任务单独核对不确定结果 |
| 配置/模板/发布版本 | 配置变更可审核可回退 | 草稿与生效分离，任务固定所用版本，历史不随新配置变化 |
| 业务记录与审计 | 可解释的状态与操作时间线 | 原始客户资料放受控业务存储；审计只记引用和脱敏摘要 |

内部任务队列可以由数据库持久任务表配合 worker 起步。报价试算等快速请求同步完成；OCR/导出/收发信使用任务 ID 查询进度。无需在第一版引入大量微服务、Kafka 或通用工作流平台。不同语言的引擎可以独立进程部署；模块划分不等于每个功能都拆一台服务器。

文件内容、OCR 文字和邮件都是业务输入，不是系统指令。识别层不能执行其中的命令、链接请求或“忽略权限”等文字；多租户文件、任务、生成件和邮件引用都必须重新校验权限。

## 九、新功能接入约定

每个新模块交付自己的用途、输入/输出、权限、配置项、数据所有权、同步/异步方式、错误状态、审计及验收样例。使用同一身份、业务单据引用、文件中心和任务基础设施。能力市场与后台消费服务端目录，不另建第二套用户或 Key。

目前仓库的通用热插拔仍是目标，不能把本规划写成已支持上传任意模块代码。首期采用随版本部署的明确模块注册；稳定后再评估制品签名、隔离加载和运行时切换。

OCR 与 SO 识别可通过窄 API/CLI/MCP 任务入口提供，但不能自动扩张现有 Key。邮件发送、正式文件导出、订舱确认分别要求明确权限和内容确认，查询型 Agent 默认只能准备草稿和读取已授权结果。新增工具名、字段、权限和操作状态在各模块 RFC/Schema 冻结后再发布，本文不创建可调用的虚构接口。

## 十、分期路线与验收

以下顺序以打通业务闭环为依据，不在源码、样本、配置和邮箱条件不明时承诺交付日期。每期功能通过后再投入使用，不等待所有扩展全部完成。

| 阶段 | 交付 | 验收标准 |
|---|---|---|
| A 当前迁移基础 | 自有报价/关务引擎、新后台空白配置；提前确定业务单据、文件、任务及版本边界 | 无旧配置默认生效；已有账号/Key 兼容；新引擎不依赖旧域名；缺配置明确拒绝 |
| B 报价闭环 | 需求→试算→审核→报价记录→PDF/Excel 导出 | 金额与来源版本一致；草稿/正式/过期区分；内部成本不泄露；文件可读回 |
| C 资料识别与 SO | 文件中心、通用 OCR、装箱单/发票字段核对、SO 上传/识别/差异/版本 | 关键字段可定位原文；重复上传不重复创建业务；修订和时区不误判；确认前不改正式字段 |
| D 邮件订舱 | 供应商联系人、邮件模板、草稿预览、授权发送、发送记录、手工导入回复/SO | 收件人/附件清单正确；变化使确认失效；不确定发送不盲目重试；发出不等于订舱确认 |
| E 收信与协作 | 限定邮箱收信、回复关联、SO 自动入待复核队列、站内待办及关键时间提醒 | 不扫描未授权邮箱；同一回复不重复建单；错配可纠正；SO 修订更新关联待办 |
| F 更广的扩展 | 批量文件、更多识别模板、更多承运商、授权 Agent 自动化 | 复用身份/任务/文件/版本，不重新改核心流程；每项有独立状态和限额 |

报价导出优先于自动发信，因为其输出与审核流程也是订舱的基础。SO 先支持手工上传，可在邮箱尚未接通时独立产生价值。OCR 与报价后台的公共基础可以在设计上同步，具体实现保持小步交付。

## 十一、验收样例与待收集资料

实际实施前收集经用户允许使用的脱敏样本，并区分开发样例和独立验收样例：

- 文件识别：清晰 PDF、扫描件、倾斜照片、多页和中英文混合；净重/毛重、单件/总计、单位和否定词案例。
- 报价导出：现用报价单样式、内部明细表、不同币种、有效期、草稿和正式条款。
- SO：不同供应商格式、修订版、取消/条件确认、缺时区、同订舱号多个版本及与申请冲突的案例。
- 邮件：常用订舱正文、收件人/抄送规则、必须附件、退信、补料、改船/改期和供应商确认的样例；邮箱连接方式在接入时核验。

不预先宣称 OCR 准确率。先统计关键字段准确率、人工纠错量、各类失败原因、端到端处理时间和重试率；置信度只用于安排复核，不证明数据正确。邮件用合成邮箱/模拟服务验证超时和幂等，再在明确授权的目标邮箱执行实际验收。生产测试不能默认给供应商发送订舱申请。
