> 本页是页面及交互提案。审批、应用和回滚按钮均为线框说明，不调用后台。现有本地受控能力不能由改版自动成为生产能力。

## 变更列表

```text
变更中心
[我的申请] [待我审批] [需处理] [全部有权限记录]

变更                 类型         范围              当前进度        操作
──────────────────────────────────────────────────────────────────────
测试询价超时调整     参数配置     部署范围          待另一人审批   [查看]
装柜摘要启停         能力启停     按真实影响展示    等待核验       [查看]
```

两种变更使用同一展示语言，但不会因此变成同一个后端操作。凭证更换等接入操作可出现在统一历史中，仍遵守各自合同，不强行套用模块发布的四眼审批规则。

可核实的具体影响从服务端读取；缺少信息时显示待核实。

───────────────────────────────────────────────────────────────

处理进度
草稿 → 已检查 → 已提交 → 等待审批 → 等待应用 → 等待核验
                              ↑ 当前步骤

申请人看到            [查看申请] [按允许动作撤回]

页面示意值不得落成默认业务配置。真实前端按已批准配置定义展示字段、范围、必填性和说明；无定义则只读。

## 能力详情里的编辑区

编辑配置在能力详情中完成：当前值与草稿有明确区别，未保存显示在页面内。主动作按顺序为“检查配置”→“查看变更预览”→“提交审批”。提交后进入这个变更详情，不继续在原表单并排展示全部后续按钮。

审批人看到不可变的修改前后、作用范围、申请理由和允许动作。批准不等于应用，更不等于实际生效。修改草稿后必须重新预览和审批。

## 各阶段的反馈

| 阶段 | 页面主文案 | 可执行动作 |
| --- | --- | --- |
| 草稿未检查 | 配置还未检查 | 检查配置 |
| 校验不通过 | 配置需要调整 | 定位错误字段 |
| 待审批 | 等待另一位有权限的管理员 | 当前申请人只查看或执行允许的撤回 |
| 已批准待应用 | 已批准，尚未应用 | 有执行权限且满足门槛时应用 |
| 正在应用 | 正在应用本次变更 | 暂停重复提交，查看当前步骤 |
| 需要重启 | 等待受控重启 | 展示影响和允许的下一步 |
| 等待核验 | 正在确认实际配置 | 读取同一操作和实际状态 |
| 核验一致 | 本次配置已核验生效 | 查看实际结果和时间 |
| 核验未知或不一致 | 尚未确认生效，需要处理 | 查看差异，按合同协调或回滚 |
| 版本冲突 | 配置已被其他操作改变 | 读取最新值并重新预览 |

不显示一个同时代表审批、应用和核验的“发布成功”。技术证据里保留 revision、digest、module generation、operation/readback 引用，正文不要求普通使用者理解它们。

## 回滚

回滚必须展示实际可回目标、影响范围和新变更记录。没有可回目标时解释原因；不提供“恢复默认”。当前本地控制面仍沿用“回滚到上一已读回版本（本地受控环境）”的语义，不能由设计稿承诺生产回滚。
