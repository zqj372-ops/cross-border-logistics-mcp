# API 统一工作台：页面与操作规格

[产品规划](11-api-native-platform-prd.md) · [接口差距](13-api-capability-gap-matrix.md) · [交付验收](14-api-platform-delivery.md)

状态：页面规格，尚未实现。下列路由均为建议命名，不是当前已经注册的接口或页面。

## 1. 外壳与导航

推荐保留 FreightClaw 品牌与现有浅色蓝色视觉。顶栏固定显示当前企业、环境、工作区切换和个人菜单。切换企业时清理当前请求与敏感结果，重新读取成员资格、授权和列表，不沿用上一企业的对象 ID 或缓存。

| 使用区 | 主导航 | 首屏目标 |
| --- | --- | --- |
| 业务 | 工作台、询价、关务查询、税费估算、货物与装柜、业务记录 | 继续当前任务或开始新业务 |
| 开发者 | 应用、API 申请、调用记录与用量、接口文档 | 知道哪个应用待处理、能调用什么、失败原因 |
| 企业管理 | 企业概览、成员与角色、企业应用、服务授权、组织审计 | 管理人员与企业内资源 |
| 平台管理 | 企业准入、API 审批、服务与连接、发布与配置、运行审计 | 处理待办并核验结果 |

凭证管理位于应用详情，避免一个独立大 Key 列表失去应用归属。平台管理不出现在普通成员导航中；有多角色的人显式切换使用区，管理身份不会自动作为业务调用身份。

移动端最多四个一级常用入口，其余通过可发现的“更多”菜单进入。企业/环境始终可辨认，不能只用颜色表示正式或测试。业务资料与结果分标签显示；切换不丢失输入。桌面采用稳定侧栏和紧凑内容区，不把每项功能都放进大卡片。

## 2. 用户与企业页面

### 登录与首次加入 · `/console/login`、`/console/welcome`

- 主动作：企业登录/验证身份。实际身份 provider 由部署配置决定，不临时生成生产密码登录替代品。
- 已获邀请：显示企业、邀请角色与有效期，验证身份后加入。身份不匹配时解释原因，不允许仅改表单中的邮箱绕过。
- 未加入企业：显示“申请企业接入”与申请进度；不进入空白管理员后台。
- 拥有多个企业：选择企业，加载相应成员权限；没有平台权限的账户不出现平台管理入口。
- 登录过期：在安全范围保留当前未提交草稿，重新登录并验证同企业权限后恢复；不自动重放写请求。

### 企业接入申请 · `/console/organization-request`

字段：企业名称、业务地区、业务用途、申请人已验证联系方式、首位负责人。需业务/合规材料时按真实运营要求另行增加，首期不默认收集证件或银行资料。

主动作：“提交企业申请”。结果显示申请编号、当前处理状态、所需补充、处理意见；只有企业准入成功并建立有效 Membership 后才能进入生产能力申请。

### 企业准入审核 · `/platform/organizations`

平台列表显示企业名称、申请人已验证身份、首位 owner、业务用途、申请版本/时间和准入状态；筛选待处理、待补充、已批准、已拒绝、已暂停。详情显示申请资料、审核历史和待创建的企业/成员关系，不显示客户 Key 或业务正文。

平台审核员可要求补充、拒绝或批准准入，必须记录原因和申请版本，不能审批本人申请。批准后分别跟踪 tenant 与首次 owner Membership 的创建及读回；只有二者都成功才显示“企业已开通”。中途失败按同一 operation 恢复，不留下看似 active、实际没有 owner 的企业。

企业暂停/恢复仅由具备对应运营权限的角色执行；确认页列出将受影响的人员会话、应用与授权。暂停后状态显示实际执行与读回结果，恢复重新核验当前权限和凭证，不恢复已吊销 Key 或已撤销 grant。

### 服务授权管理 · `/console/organization/service-grants`

企业 owner/admin 可查看本企业授权，列表显示授权对象（企业 Web 或具体应用）、服务、精确动作、渠道、环境、状态、有效期、来源申请版本。详情展示当前权限、限制、连接证据、开通操作与历史变更；业务记录和 Key 明文不在此页显示。

允许动作：提交扩权/续期申请、主动暂停使用、申请恢复、撤销授权。暂停/撤销显示影响对象与生效边界并要求明确确认；企业管理员不能自行扩大平台批准范围、修改到期时间或把测试授权改为正式。

状态由服务器读回：active→suspended/revoked/expired；缩权产生新授权版本并展示差异。已撤销/过期的授权需新申请/新版本，不能点“恢复”自动复活；已获准的暂停恢复也要重新核验连接与目录。申请进度和原授权状态分别显示，续期申请在审核中不延长原授权有效期。

### 成员与邀请 · `/console/organization/members`

列表列：姓名、验证身份、角色、状态、邀请/加入时间、拥有的应用数量。可搜索与筛选，不在普通列表显示身份 provider 内部 Token 或敏感登录元数据。

主动作：“邀请成员”。邀请表单为身份、角色与说明；仅能授予自己有权分配的企业角色。默认授予业务操作员或开发者，不预选所有者/管理员。

行操作：重发邀请、撤销邀请、调整角色、暂停成员、移交应用、移除成员。调整角色先显示新增/失去能力；移除唯一应用负责人或最后一位企业所有者时，给出具体待处理对象和跳转到站内移交步骤。

成员详情显示所属企业与权限、负责应用和脱敏审计。企业管理员无法搜索全平台用户并获知其他企业关系。

### 个人账户与安全 · `/console/account`

显示个人资料、已验证的登录身份、加入的企业、登录方式和当前会话。姓名等平台资料与 IdP 负责的邮箱/密码/多因素认证分别标明来源；修改登录身份、找回账号、重置密码与 MFA 通过身份 provider 的受控流程完成，不在平台复制密码库。

支持退出当前会话、退出其他会话（provider/会话合同实现后开放）与查看近期脱敏安全事件。邮箱或身份发生变化必须重新验证后更新绑定，不能靠修改显示字段接管邀请或应用；不允许在此页查看机器 Key。

## 3. 应用、申请、凭证与验证

### 我的应用 · `/console/developer/apps`

主动作：“创建应用”。初始字段：名称、用途、负责人、REST/MCP 接入方式、测试/正式环境。创建成功产生稳定 client ID，显示“尚未申请服务”，不同时签发 Key。

应用列表列：应用名、负责人、环境、已开通能力数、待办、最近调用状态。不要用一个绿色圆点概括申请、授权、连接和调用四种状态。

应用详情标签：概览、服务与申请、凭证、接入指引、调用记录、设置。页头始终显示当前应用和企业，所有操作依据服务器读回的应用版本执行。

### API 申请 · `/console/developer/apps/:id/requests/new`

```text
应用：ERP 物流接入（示例名称）       企业 / 正式环境

1 应用资料 ── 2 选择服务 ── 3 确认提交

服务            请求动作             当前资格
关务查询        查询 / 确认候选       可申请，来源待核验
税费估算        单项 / 批量           接口待接入
报价            试算                 可申请，来源待核验
报价记录        保存 / 查看 / 复核    独立权限

用途、预计日调用量与峰值、技术联系人
                                [保存草稿] [下一步]
```

上图仅示范结构，名称与状态不是生产数据。实际服务选项来自当前受控能力目录；尚未提供的服务可记录需求但不承诺立即开通，界面必须区分“提交开通申请”和“登记需求”。

确认页逐项列出请求能力、读写性质、数据范围、环境、期限和配额申请。原有能力续用与新增能力明显区分；不使用“全部服务”默认全选。提交成功展示申请编号与下一个责任角色。

待补充时可编辑指定字段并重提新版本；已批准/拒绝申请不可原地修改。重提、撤回与再次申请有明确版本关联。重复提交或网络超时先按操作 ID 查状态。

### API 审批 · `/platform/access-requests`

列表以待处理为默认：企业、应用、申请用途、环境、新增操作、申请时间、状态和责任审核人。详情呈现申请快照、当前已授予权限、本次增减、服务资格及相关审核记录。

动作：批准全部、部分批准、要求补充、拒绝。批准前显示“将授予什么、给谁、在哪个环境、有效多久”；危险或写能力单独展示。审核人不能自审，不拿管理身份执行客户业务验证，也不见客户 Key。

批准后留在详情跟踪：已批准→权限写入→读回→连接核验。任何一步失败显示具体操作编号与恢复按钮；“批准”按钮成功不能把整条流程标绿。

### 凭证 · `/console/developer/apps/:id/credentials`

列表列：名称/前缀、状态、权限版本、到期时间、最后使用时间、交付状态。只有应用负责人/明确维护者可以创建和领取；企业管理员默认可暂停和移交，但不能从列表恢复别人领取的 Key。

“创建 Key”先选择该应用已获准权限的子集与有效期。后端重新校验申请授权和精确动作，不能信任页面提交的 scope。申请审批动作不生成 Key。

一次性交付界面先显示完整 Key、保存说明、复制与确认交付；离开后不可恢复。若响应丢失，页面按操作 ID 核验；明确未取得 Key 时吊销待交付版本并重发。不能用再次点击覆盖未知结果。

轮换先展示权限差异和旧 Key 失效时点。首期沿用立即吊销旧 Key 的合同，明确会中断调用；平滑轮换需另行实现 successor 和有界重叠窗口。安全事件使用明确的立即吊销动作。

### 接入指引与诊断 · `/console/developer/apps/:id/connect`

显示当前环境的实际服务器端点、认证方式、精确可调用能力、版本化请求/响应示例和错误恢复。不向开发者暴露两个原业务服务的后台密钥或私有地址。

REST 与 MCP 两个标签共用申请和应用。REST 示例使用短期 Bearer 并验证 audience；MCP 指引包含换票、initialize、tools/list 与一次授权工具调用。所有示例中的 secret 使用占位符。

“检查接入状态”读取服务端脱敏证据，不要求用户把 Key 粘贴进网页或聊天。平台自检、客户应用调用与业务数据有效性分别显示：时间、环境、授权版本、服务版本、结果及 request ID。

### 调用记录与用量 · `/console/developer/apps/:id/calls`

按时间、服务、操作、状态筛选。列表包含 request ID、耗时、状态、来源环境、错误类别和受控 trace 摘要；详情默认无客户地址、商品材料全文或 Key。业务数据权限不从开发者诊断权限继承。

当前只规划调用次数、成功/补输入/人工复核/不可用分布、技术限流事件。缺少真实计数时显示“暂无可核验数据”；商业额度/计费另行定义，不生成装饰性统计数字。

## 4. 业务页面

### 统一工作台 · `/console`

首屏是“继续处理”列表和三个主任务：新建询价、查询关务、估算税费。列表显示当前业务对象、待补字段/待复核原因、最后更新时间与责任人。来源状态折叠在次级区，只有阻断当前任务时上浮显示原因。

没有记录时给出清楚的新建动作，不填充假报价。没有业务权限时提示缺少哪项授权、谁可申请，并提供站内申请/联系管理员路径。

### 询价 · `/console/quotes/new`

桌面：左侧资料、右侧结果；手机：资料/结果两个标签。原话输入与结构化编辑是同一份草稿，AI 提取后标注“需确认”，用户可修改字段。

资料包括明确起运仓、目的地/邮编、地址性质、包装与件数、重量/尺寸/体积、实体托盘、附加服务。不要默认商业地址、默认包装或从邮编推断未经确认的仓库。

主动作：“试算报价”。提交前显示缺项，提交中禁止重复；改动相关输入时结果标为过期。结果显示源币种、费用分项、计费依据、有效期、风险、来源版本；不能把 USD 改成 CAD 标签冒充换汇。

结果动作：“保存到报价记录”“提交人工复核”是独立权限和写操作。保存/复核未接入时明确不可用原因，不以原网页跳转作为完成途径。发送客户/订舱没有权限和合同则不出现可执行按钮。

### 关务查询 · `/console/customs`

查询表单包括商品或编码、规则日期、编码所属国、材质用途；当前 M2M 商品原产国固定 CN，其他原产国需新合同，不提供无实际能力的全球选项。

查询后在同一页插入追问或候选列表。选择候选后保留原 query/ruleDate/attributes，并提交 selectedHs6；M2M 不接受公共浏览器接口的 querySessionId。后端处理真正的来源状态与版本核验。

结果按 CN/US/CA 展示；各国完整税号、税率原文、确认情况、措施、资料和来源在同一业务上下文。来源文档可作为证据链接，但主查询和后续操作始终在工作台内完成。站内“估算税费”只带入已确认事实与来源引用，货值等新信息仍需补充。

### 税费估算 · `/console/customs/estimate`

支持单项和 Excel 批量。批量先解析并确认行项，再提交有界服务器任务；超上限在提交前说明限制，不默默截断。若执行耗时超过同步预算，显示任务状态、已处理行数、失败行与查询进度，不无限轮询。

输入货值、币种、数量单位、目的国、原产国、规则日期和所需运保费。结果逐项展示计税基础、税费、汇率日期、来源、排除项和人工复核原因。只有已成功且币种/覆盖一致的项目可汇总；部分失败显示“部分完成”，不可算成整单零税或正式总价。

### 业务记录与人工复核 · `/console/records`

使用类型标签区分报价记录、关务记录、估算与复核。列表只显示有授权且可从来源恢复的记录；当前原系统无恢复能力的查询不承诺“历史已保存”。

详情从原系统受权读取，并展示原业务 ID、状态、输入版本、来源版本和当前是否过期。复核操作展示修改内容与通知影响，服务端确认权限和版本后执行；成功以原任务读回为准。

## 5. 通用状态与验证矩阵

| 情况 | 页面必须给出的内容与动作 |
| --- | --- |
| 没有成员资格/服务权限 | 清楚说明对象、缺少权限与站内申请/管理员处理路径，不出现伪造空结果 |
| 加载/提交中 | 保留原输入与上下文；禁用重复提交；读取请求可取消，取消浏览器等待不等于上游任务取消 |
| 需要补充 | 字段级错误与完整问题，焦点移到错误摘要或首个字段，修改后废弃旧结果 |
| 来源暂不可用 | 显示原因、检查时间、request ID 和重试；不降级到测试价格或网页跳转 |
| 写请求结果未知 | 以 operation ID 查询与恢复，不自动重新保存/发任务/签发 Key |
| 会话过期 | 重新登录后验证身份和企业再恢复，敏感数据不跨身份重现 |
| 申请/授权版本冲突 | 重新读取并比较变化，不覆盖他人的决定 |
| 部分成功 | 明确成功范围和失败范围；失败行可单独重试，汇总注明排除项 |

验证视口至少包含桌面 1440px、手机 390px，并检查 320px 和 768px 无页面级水平溢出。键盘可访问全部主动作，菜单/对话框关闭后恢复焦点，字段错误与输入建立语义关联。证据按实际页面与真实状态截图，不用原入口版截图宣称新版完成。
