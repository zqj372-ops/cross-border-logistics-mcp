## 产品决策

建议采用 **两个业务服务保留权威，FreightClaw 统一入口、交接与 Agent 接入** 的结构。原报价服务继续完成询价和人工处理，RiskCustoms 继续完成关务查询与估算。MCP 不再建设第二套完整报价表单、三国税率卡片、客户回复或税费计算器。

上一版 Admin 中的资料准备表单是交互草稿，不是新的业务权威。用户同意执行后，已用原服务入口与流程指引替换，旧草稿只保留文档和截图记录。先复用已经存在的业务页面，再解决接口和资料交接缺口。

**一期实施读回：** 用户指定 `https://quote.freightclaw.net` 和 `https://clearddp.com`。本地 Admin 已通过独立只读入口元数据，提供报价、AI 报价、异常处理、关务查询和税费计算器五个固定链接；共 11 个导航页面。没有在前端写默认生产地址，没有更改两个源服务，也没有连接生产业务接口。入口配置、未知访问状态和 MCP 接入状态分别展示。见[实现与验证](07-implementation.md)和[入口配置说明](../../runbooks/admin-business-entrypoints.md)。

两个目标分别推进：

- **人使用：** 从同一工作台进入原报价、关务页面，保持现有业务流程；逐步实现带资料跳转和返回结果。
- **Agent 使用：** 通过 MCP 调用经过合同核验的窄能力；服务账号、租户、业务权限和结果证据在服务器端验证。

## 已有功能怎么复用

| 现有能力 | 当前代码实际提供 | 联合产品中的处理 |
| --- | --- | --- |
| 报价销售工作台 | /quote：录入、解析、核对、计价、风险、客户文案复制/文本导出、记录回看 | 完整沿用，作为人工询价主工作区 |
| AI 报价 | /ai-quote：客户原话、抽取、字段核对、可选自动计价 | 沿用原页面和模型配置；MCP 不再复制解析与确认界面 |
| 人工业务处理 | /ops：人工任务、诊断、学习与审计；销售记录和人工报价处理已有接口 | 继续由报价服务管理，不在 MCP 新建同类任务系统 |
| 关务查询 | /：中国出口视角的中、美、加编码、税率、措施、文件及来源；支持候选确认 | 完整沿用三国工作台，不把整个产品缩成 MCP 当前的 CN→CA 子集 |
| 税费估算 | /calculator：美加单项、Excel 导入、汇率和需人工复核项目 | 先复用原计算器；Agent 估算接口另行补齐 |
| Agent 与租户接入 | MCP / Access Gateway 的身份、精确授权、审计、模块发布 | 在既有边界内复用；不把原网站登录或页面可见当作 MCP 权限 |

报价的 Zone、FSA、计费托数、价格矩阵、附加费、规则和报价记录继续归报价服务。关务的归类、税率、措施、文件、来源发布、汇率和估算规则继续归 RiskCustoms。MCP 只持有必要的请求关联、opaque 引用、脱敏状态、授权与运行证据；不复制两套业务数据库。

## 前端组织与操作流程

~~~text
FreightClaw 工作台
├── 开始询价       → 原报价服务 /quote 或 /ai-quote
├── 查询关务       → RiskCustoms /
├── 估算进口税费   → RiskCustoms /calculator
├── 处理报价异常   → 原报价服务 /ops（仍按原角色权限）
└── 平台管理       → 能力、接入、配置、授权、发布与审计
~~~

业务人员首先看到任务入口。管理功能保留原有页面，不要求业务人员先理解工具名、发布版本或凭证结构。

每个业务入口分别表达三件事：**原业务页面、当前数据就绪情况、MCP 接入情况**。现在 MCP 的来源卡主要是固定的接入说明，不能拿来推断原服务是否在线。原业务入口可达也不能反过来证明 MCP 已接通。

一期使用普通页面跳转或新标签页。关务 Nginx 模板有 SAMEORIGIN 限制，报价页面也没有验证过部署端嵌入策略；不以 iframe 作为当前集成前提。本次代码核查未发现两套服务间已实现的共同 SSO，先按各自身份机制运行：报价保持用户/Key 与角色，关务现有浏览器查询保持其匿名/限流边界；不会转发浏览器 Cookie 或把上游长期 Key 放进统一工作台。

入口地址由部署方维护环境/组织级允许列表和适用角色，不能接受页面参数、用户输入或上游快照中的任意 URL。未配置或当前角色不可用时显示具体原因，不提供可点击入口。已配置可信入口但尚未核验可达性时显示“访问状态未验证”，可以由用户打开原页面；不能把未知状态写成在线或故障，也不能据此启用 Agent 业务调用。

### UI 的联合改进

统一工作台采用任务入口和待办布局：主区域突出“开始询价”“查询关务”“估算进口税费”，每项说明能做什么、进入哪个业务服务。平台管理放次一级导航。业务人员不需要先选择 MCP 工具或配置凭证。

两套原页面后续使用共同的字体、间距、按钮层级、错误提示与返回入口，业务布局仍按任务保留：报价围绕资料核对、费用与风险、原记录和人工处理；关务围绕查询输入、候选确认、三国结果对照与税费估算。共享的是视觉规范和交互约定，价格表、税率卡片、计算器与业务状态仍由原服务维护。两个上游的视觉调整属于后续各自仓库的工作，本次未修改。

联合结果页属于资料交接完成后的阶段，由 FreightClaw 浏览器渲染当前会话的临时对照视图，受控服务端分别按原系统权限回读报价和关务引用。它不保存完整业务结果，也不创建统一业务主记录；报价记录留在报价服务，关务只引用它实际拥有的查询/发布证据。原关务尚无结果恢复存储时必须先补合同，不能声称已有历史结果。需要持久化联合业务记录时，另行决定所有者和合同，不默认落到 MCP。

视图优先并列显示运输报价、关务查询和税费估算各自的状态、适用日期、币种、来源与“回到原服务”。未核对币种、费用覆盖与重复计入前，不显示跨服务合计。缺少已实现的结果回读时，入口只叫“打开工作台”，不叫“查看本票结果”。

### 一票业务的目标旅程

~~~mermaid
flowchart LR
  A[同一工作台选择业务] --> Q[原报价工作台]
  A --> C[原关务工作台]
  Q --> Q1[报价引擎 / 原人工处理]
  C --> C1[归类 / 税率 / 措施 / 来源]
  C1 --> E[原税费计算器]
  Q1 -. 后续受控引用交接 .-> R[联合结果对照]
  C1 -. 后续受控引用交接 .-> R
  E -. 后续受控引用交接 .-> R
  G[Agent] --> M[MCP 身份与精确权限]
  M --> QA[待补齐的报价只读接口]
  M --> CA[现有 RiskCustoms M2M]
  QA --> Q1
  CA --> C1
~~~

实线表示业务归属与调用方向，图中不表示接口已经连通；虚线的跨服务结果交接尚需新增合同。

联合作业的目标是：在原报价工作台核对货物，遇到需要查询的商品时转到关务服务；确认目的国编码、税率和措施后返回同一业务上下文。运输报价与关务结果分别保留状态、单位、有效日期和来源，不能用其中一个成功状态覆盖另一个未确认状态。

**当前还不能承诺“一次输入自动带入、打开同一份结果”。** 报价页没有某票 URL 定位；关务主页没有 URL 预填或结果恢复 API。第一期先完成正确入口，资料交接是下一项独立交付。

## 报价服务：先复用完整工作台，再补真正的只读接口

此前仅从 MCP 侧看 Quote V2 adapter，容易把“候选合同有实现”误解成“原服务接口已经符合合同”。跨库核查确认，两者尚不能直接连接。

| 方面 | MCP 期待 | 原报价服务现状 | 必须补齐 |
| --- | --- | --- | --- |
| 路由 | POST /quotes/zone-preview | 只有 POST /quotes/zone-calculate；AI 使用 /quotes/ai-auto-quote | 新的只读服务入口，或经过 RFC 调整双方合同 |
| 操作性质 | 只读报价试算 | 计价会写业务审计/诊断，必要时创建人工任务或通知；AI 只抽取也会写销售记录 | 分离确定性计算与业务落库/通知，不能换个接口名字继续调用原写流程 |
| 输入 | tenant_id、origin、effective_date、quote | quote 和通知字段；不接受上述外层上下文 | 明确字段映射、始发地和日期规则 |
| 身份 | 服务器绑定租户和精确工具权限 | 用户或 API Key + 角色；没有 tenant 隔离模型 | 单租户实例的明确映射，或先完成上游多租户隔离；不能只加 tenant 标签 |
| 输出 | 费用行、版本、有效期、ready/test、release/hash、来源证据 | quote_id、费用字段、风险和销售说明；缺少这套发布证据 | 由报价服务生成可信的发布和结果证据；MCP 不补造 hash、有效期或版本 |
| 业务动作 | 当前 MCP 结果 sendable=false | 原业务工作台具有记录、客户回复及可选通知流程 | 原服务原有授权动作保持独立；MCP 不继承发送权限 |

推荐在原报价服务内抽出可复用的计算阶段，使现有计价流程和新的只读入口使用同一套引擎、同一份获准规则。业务只读可以保留必须的脱敏访问审计；它不能顺带创建报价/销售记录、人工任务、发通知或修改规则。不要关闭安全审计来声称“零副作用”。

这项工作还包括发布证据、日期和租户访问合同，不能估成一个转发函数。前端页面和引擎都能复用，MCP 接口边界需要认真补齐。

## RiskCustoms：复用现成 M2M，补全 MCP 结果投影

原服务源码中已有 M2M status/query 合同、Bearer + X-Tenant-Id、凭据与租户绑定、发布快照前后复核、ready/test 门禁和审计失败闭合实现。输出合同已包含三国结果、税率、确认合计、措施、文件、来源和发布身份。生产端点、凭证、租户映射、正式数据发布以及 status→query 实际读回均未在本次验证。

目前的信息损失发生在 MCP 内：

- 固定 codeCountry=CA，并只保留加拿大结果；整个原服务实际支持中、美、加对照。
- 税率、confirmedTotalPercent、措施、文件和结果警告没有进入 MCP 输出。
- 结构化下一问题被压成文字，丢失 attribute/options，难以可靠完成追问。
- 来源元数据与完整发布身份只部分保留，很多信息参与了校验却未供调用方展示。

推荐先保留既有 customs.ca.search 的兼容行为，通过新版本合同定义完整关务结果或窄结果引用。需要其他国家时明确新增/扩展工具的国家范围，不能在同名加拿大工具中悄悄扩大语义。批准合同后再改 MCP 映射与新生产 profile。

### 税费估算已有页面，没有 M2M 估算接口

原 /calculator 在浏览器调用 /api/query 和 /api/exchange-rates?asOf=…，然后使用 tariff-calc.ts 的 convertValue、estimateTariffBreakdown 运算。批量是浏览器逐码请求，不是已有批量 API。核心已经使用 Decimal，金额结果为字符串，但当前表单货值输入类型为 number。

一期直接进入这个已有计算器。若以后开放 Agent 估算，把同一确定性核心放到 RiskCustoms 自己的共享计算层和受控服务端入口，补齐 decimal string 输入、单位、汇率/税则快照、版本和人工复核规则。不要在 MCP 复制另一份公式，也不要把原匿名 browser API 拼成已经存在的 M2M estimate。

## 最小资料交接怎么做

### 可以直接确认的入口

| 服务 | 当前支持的页面路径 | 尚不支持 |
| --- | --- | --- |
| 报价 | /quote、/ai-quote、/ops | URL 预填、按 quote_id 打开某票 |
| 关务查询 | / | query/ruleDate/selectedHs6 URL 预填、按 queryId 恢复结果 |
| 关务估算 | /calculator?name=…&hs=…&country=US或CA | URL 传规则日期、完整确认结果、来源快照 |

当前计算器确实支持这些窄预填参数，但商品名称和税号不能自动视为低敏信息；参数可能进入浏览器历史、代理日志和 Referrer。只对经过数据分类允许的公开字段、由当前用户明确发起且目标域可信的跳转使用它们；客户业务资料默认使用下述短期引用。预填不携带已确认结果的权威，货值、地址、客户原话、凭证或完整材料不放进 URL。

### 推荐的新交接合同（提案，尚未实现）

由资料所属服务创建短期、一次性 opaque handoff_id，链接只携带该引用。接收服务验证当前身份、组织映射、用途、有效期及允许字段后领取资料；预填后仍由操作员确认，不自动计价、不通知。来源应用和返回地址按配置白名单决定，不接受任意 return URL。

交接服务在服务器端绑定签发方、接收方、tenant/actor、用途、允许字段、原业务引用和失效时间，服务间调用需认证。单次领取原子执行，至少区分待领取、已领取、已过期、已撤销；这些是交接对象状态，不扩展 MCP 五状态包络。超时后先读回是否已领取，不能盲目重发造成重复处理；审计只保存脱敏引用和状态。

接收服务完成用户确认后，通过受认证的回传端点或短期返回引用，把结果引用交还发起服务/临时对照视图。返回引用绑定原 handoff_id、原业务上下文、接收对象与目的，并保留原结果状态、确认状态、版本和来源快照；回传成功只代表引用已交付。展示前仍要向来源做有权限的结果回读，重新验证状态与有效期。若来源没有恢复 API，先交付明确标注的“交接已完成”状态，不能伪造原结果或使用 queryId 重新查询后声称恢复了旧结果。

MCP 不成为这份业务草稿的保存系统。若由 MCP 发起，资料通过经批准的接收接口交给原业务服务，只保留必要引用和交接状态。匿名关务 Web 会话不能直接冒充企业租户，需要受控领取端点和明确的用户/组织绑定。

| 信息 | 可复用方式 | 不能混用的语义 |
| --- | --- | --- |
| 商品描述、材质、用途 | 保留来源，供关务补充确认 | AI 抽取不是正式归类 |
| 目的国与商品原产国 | 分别显式记录 | 发货仓库所在国不等于商品原产国 |
| 包装、实重、尺寸、体积 | 从已确认货物事实交接给报价 | 不用 MCP 的独立计算覆盖报价服务的计费规则 |
| 件数与申报数量 | 按单位和商品项核对 | 包装件数不能自动当报关商品数量 |
| HS6 与各国税号 | 保留国家、候选/确认状态及来源 | 同一 HS6 不等于各国完整税号相同 |
| 申报货值、币种 | 由用户提供给关务估算 | 运费金额不能当作申报货值 |
| quote_id、queryId、发布快照 | 作为各自命名空间的引用 | ID 本身不是访问授权，也不证明当前已经有恢复接口 |

修改目的地、包装、尺寸或重量后，运输报价必须重新核对；修改商品属性、原产国、HS、规则日期或货值后，相关关务结果必须重新核对。界面保留“上次结果已过期”的明确状态，禁止把旧结果继续显示为本次结果。

## 实施顺序与验收

| 阶段 | 最小交付 | 验收 |
| --- | --- | --- |
| 1. 入口与职责 | 统一业务导航，沿用两套原页面；显示原服务与 MCP 的独立状态 | 路径、部署地址及原角色权限在授权环境核验；链接不伪称预填/SSO/结果恢复 |
| 2. 关务 Agent 接入 | 复用源码中的 M2M 合同与实现，扩展被丢失的结果字段，建立受控新 profile | 本地 fixture 验证后，在授权环境核验 endpoint、身份/租户、正式发布及 status→query 读回；国家/候选不误映射；税率/措施/来源完整；快照变化、未就绪、越权均失败闭合 |
| 3. 报价 Agent 接入 | 同引擎的独立只读入口、字段/身份映射、版本和发布读模型 | 不创建业务记录/人工任务/通知；输入输出与真实服务匹配；租户、有效期、来源和金额分项可核验 |
| 4. 资料与结果交接 | 短期 handoff、结果引用返回、受权 quote_id 回看、关务结果恢复或引用回读 | 过期/重复领取/跨组织被拒绝；回传关联原业务且重新受权读取；超时查状态；预填后人工确认；修改输入使旧结果失效；不创建 MCP 业务主记录 |
| 5. 按需要统一登录与估算 API | 企业身份映射、RiskCustoms 服务端估算 | 仍由原服务执行业务权限；前后端同一计算核心与同一版本证据；不默默继承发送/写权限 |

人工业务入口可以先联合；技术自动接入建议关务 M2M 先于报价只读入口，因为前者源码中已有双方对应合同与门禁实现，后者当前路由、身份和响应均不匹配。这是本地接口兼容性的判断，不是生产可用性排序；两者正式发布都要取得授权目标环境的读回证据。估算页面可立即纳入入口设计，M2M 估算是后续独立交付。

当前 t0-v1 三工具权限保持原样。共享字段、浏览器交接、生产 profile 和新增工具变化先按仓库规则提交 RFC，基线接受后由对应所有者实施。产品方案不是已接受合同或生产启用授权。
