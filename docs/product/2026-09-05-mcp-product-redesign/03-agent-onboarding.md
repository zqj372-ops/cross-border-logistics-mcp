## 第一步：对象

```text
接入一个 Agent
对象 ─ 能力 ─ 确认 ─ 安全交付 ─ 连接验证

组织                [选择已有组织                         ▾]
Agent               [选择已有 Agent                       ▾]
                    或 [新接入一个 Agent]

新 Agent 名称       [                                     ]
客户端              [Codex / ChatGPT / 企业助手 / 其他受支持客户端]
用途说明（可选）    [                                     ]

高级详情：显示已分配的技术标识，不要求普通用户背诵 ID。
                                              [取消] [下一步]
```

首次签发会同时创建调用方时，当前步骤仅收集草稿，确认页说明实际副作用。不能在尚未创建时显示“Agent 创建成功”。无组织时引导有权限的管理员先创建组织，或者申请加入；不会默认创建未知组织。

## 第二步：能力

```text
为“示例客服助手”选择能力

□ 货物体积与计费重       根据货物证据与规则计算。
□ 装柜容量摘要           理论容量与超限摘要，不承诺现场可装。

接入辅助
□ Agent 使用说明         允许读取当前工具的标准和上下文。

不可分配到正式环境
Freightcom 测试询价       仅限测试。[查看原因]
加拿大尾程报价            正式合同待验证。[查看缺项]

已选：按用户当前选择实时列出；没有预选全部工具。
                                              [上一步] [下一步]
```

资格、权限和工具集合由服务端决定；用户界面分类不能新增隐式授权。若接入辅助被确定为必选依赖，必须先有相应合同和产品规则，不能由前端偷偷勾选。

## 第三步：确认

```text
确认接入设置

组织                 示例组织 A
Agent                示例客服助手（将随首次签发创建）
能力                 按实际选择显示
有效期               [服务端允许的选项 ▾]

将执行
• 为指定调用方签发凭证。
• 只授予摘要中列出的工具权限。

可展开：精确工具清单、技术标识、允许操作依据。
                             [上一步] [确认创建并签发]
```

按钮名称必须匹配实际动作。如果只是向导草稿，不出现“保存成功”；如果会创建对象和签发凭证，必须在确认摘要中同时写出。

## 第四步：安全交付

```text
凭证已签发，等待安全交付

适用组织：示例组织 A       适用 Agent：示例客服助手

[完整凭证仅本次显示，此线框不包含凭证]       [复制]

复制后放入受控的客户端凭证配置位置。
不要粘贴到聊天、文档、截图或分享链接中。

[我已安全保存]    [稍后处理]
```

点击确认后等待服务端交付状态；成功再进入连接步骤。复制按钮不能充当已交付证明。中途离开以后，列表显示“待交付”；若完整 Key 已不可恢复，提供更换流程及影响说明。

## 第五步：连接与验证

```text
连接“示例客服助手”

1  获取受支持的客户端配置            [查看步骤] [下载无密钥配置]
2  在客户端设置凭证并连接            [查看指引]
3  检查服务端链路与工具目录          [开始服务端检查]
4  完成目标客户端验证                [查看验证步骤]

验证结果（示例状态）
  服务端检查          通过
  工具目录一致性      通过
  目标客户端证据      尚未取得

  服务端检查通过，客户端仍待验证。
  本次没有取得目标客户端调用证据，不能标记接入完成。

[返回 Agent 详情]   [查看检查依据]
```

本步骤是目标体验，当前客户端验证能力需补齐。不能通过点击“我已连接”伪造成功。证据至少区分检查来源、环境、目标 Agent、预期/实际工具集合及时间；有实际调用验收时再单独记录通过的工具与场景。

当前也没有已核实的 Console 主动 MCP 探测接口。仅查询现有凭证状态或 readiness 时，应显示“凭证/配置状态已确认”；只有实际完成受认证的 MCP initialize + tools/list 后，才出现“服务端目录检查通过”。

只有凭证、配置文件或浏览器探测，不能显示“Codex 已接通”。目标客户端目录读回通过，也只能证明目录层验证；不覆盖其他工具的上游 readiness 或正式环境资格。

               [调整权限]

调整权限时先展示新增、保留、移除。确认更换前提示旧 Key 将失效，更新客户端前可能中断；不承诺零中断。实际能力调整沿现有轮换语义执行，不创建全局勾选值的隐式依赖。

## 失败处理

| 情况 | 反馈 | 下一步 |
| --- | --- | --- |
| 同名 Agent 或标识冲突 | 保留输入，提示已有对象 | 选择已有对象或修改名称 |
| 没有权限 | 指明当前角色可做什么 | 返回允许页面或申请管理员处理 |
| 签发结果未知 | 未确认签发结果 | 先查询同一操作，不反复签发 |
| Key 已签发但交付未确认 | 待交付 | 继续交付；不可找回时按更换流程 |
| 目录不一致 | 需复核 | 展示缺少/多出的工具，不扩大权限补平 |
| 凭证已过期或撤销 | 接入受阻 | 进入目标凭证处理，不要求重做所有表单 |
