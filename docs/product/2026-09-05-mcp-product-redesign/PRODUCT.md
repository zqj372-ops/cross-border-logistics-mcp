## 已确认的本轮任务

- 用户要求使用 5.6 模型子代理读取代码，重新规划 MCP 服务器。
- 用户随后明确重点是“前端页面，操作逻辑，基本都是在产品经理的方面”。
- 本轮交付产品方案、页面线框和操作规则；不据此改变后端合同或生产资格。
- 用户追加要求把关税查询和正式询价纳入产品，曾批准按已有两个服务联合复用。已有 Admin 入口版与税费估算入口保留为历史实现。
- 用户最新明确所有服务通过 API 连接、不走业务网页跳转，并增加用户管理和 API 申请界面；已确认允许按方案在两个原服务的独立分支继续改造。本轮据当前本地工作树完成产品规划，见 [API 平台 PRD](11-api-native-platform-prd.md)。

## 产品目的与用户假设

产品目标是统一 API 业务与接入平台：业务人员在站内完成询价、关务与税费；开发者申请精确 API/MCP 能力；企业管理员管理人员、应用和权限；平台审核员管理准入、开通与运行。原服务拥有规则、业务数据和正式记录，工作台经服务器 API 使用其能力。原网页跳转不再作为目标方案。

首期默认内部员工＋受邀企业客户，客户范围仍允许用户纠正。人员账号、企业成员、应用与 Key 是不同对象；Application 扩展现有 Client，Agent 作为使用方式。网页业务用户不需要自行填写 API Key。角色名称是产品分工，不替代服务端权限。

## 现有产品与证据

- `apps/admin/`：11 个导航页面；首页、询价、关务和税费估算为常用业务入口，其余七页保留平台管理。
- `apps/admin/business-services.js`：闭合入口元数据验证、首页及原服务入口页面。配置读取与 snapshot 独立，异常可重试，不采集或传递业务资料。
- `src/logistics_mcp/server/admin-business-entrypoints.ts`：把管理员设置的两个规范 origin 投影成五个固定链接，无外部探测、默认地址或业务权限扩展。
- `apps/access-console/`：组织、调用方、凭证、权限及操作核验页面。
- `apps/freightcom-quote/`：独立的 Freightcom 本地测试询价页面。
- `docs/product/2026-08-31-plugin-capability-center-prd.md`：工作区已有 PRD 草稿，其文内记录统一能力中心和首批受控配置方向。
- `docs/superpowers/specs/2026-08-22-agent-guided-logistics-plugin-builder-design.md`：Agent 引导构建的既有设计。

MCP 判断基于 `codex/tenant-api-key-control` / `34e1e9567440e768eb9e7a1b6cfe8c2ded70baed`；两个原服务最新本地 HEAD 与工作树状态列在 [API 能力清单](13-api-capability-gap-matrix.md)。本轮没有取得远端最新代码、真实生产部署、客户端连接或业务 API 就绪证据。

## 必须保留的产品事实

- 货物计算和装柜理论摘要已有确定性实现；装柜摘要不等于现场可装承诺。
- Agent 使用说明是接入辅助能力，不能包装成第三项物流业务。
- Freightcom 是测试询价；Quote、RiskCustoms 等能力的生产资格不能由页面或静态源码推断。
- 原 RiskCustoms 已有中、美、加查询结果和美加税费计算器。当前 MCP adapter 只投影 CN→CA 子集，丢弃税率、措施和文档；M2M 原响应包含这些字段。`customs.ca.estimate` 固定不可用，原计算器在浏览器计算，尚无 M2M estimate。
- 用户已有报价服务是本次复用对象；Freightcom 正式资格在全服务路线图中单独验收，不因测试页面存在而获得生产资格。技术接入先关务 M2M，再补报价只读与服务器估算。
- 加拿大尾程 v2 的严格合同与 adapter 只在 MCP 侧成立；原报价服务没有 `/quotes/zone-preview`，真实计价接口存在业务写入，且缺少对应租户/日期/发布证据。不能仅装配到 runtime 就宣称完成复用。Freightcom 生产调用仍在代码中硬禁用。
- 当前生产 `t0-v1` 仍只允许货物、装柜和 Agent 上下文三个工具；新增浏览器会话调用、业务权限和生产工具集必须走新的 RFC 与发布流程，不能直接扩权。
- 配置修改、能力授权、客户端连接和正式环境资格是不同事实。
- 完整凭证只显示一次；权限调整通过轮换，不能表现为原凭证无感改权。
- 配置变更沿现有校验、预览、另一位管理员审批、应用和结果核验执行。
- 业务价格、Zone、税率和业务记录由原系统拥有；管理页面不提供这些规则的自由编辑。

## 品牌与表达

保留 FreightClaw 名称和中文操作界面，继承已经实现的浅色蓝色设计系统。新业务表单与结果取代大面积跳转入口；主流程优先使用业务语言，技术标识和证据放入详情。本轮仅规划页面，未生成新版截图或改写 DESIGN.md 的实际视觉记录。

## 实施时收敛的配置与边界

- 服务端估算 API 已纳入要求；批量上限、保留期、正式数据与配额依据真实运营合同确定。
- 两套服务的获准 API 地址、人员 IdP、服务器身份与企业映射、原记录保存与恢复合同。
- 用户首期准入默认邀请制；正式 API 申请人与平台审核人分离，批准、授权、连接、实际调用分别核验。
- 客户门户推荐新增 `/console/` 与同源 API，复用现有应用服务；现有 loopback Admin 继续作为受限运维面，不能直接放宽为客户门户。
