# FreightClaw 能力市场与简化接入

更新：2026-09-06。用户在真实开户、应用申请和凭证交付后指出流程繁琐，要求只有一套凭证，并以当前 Edge 中的 Wind Alice Market 为主要参考。本文替代此前把应用申请、两类 Key 和换票验证作为首次使用主任务的设计。

## 已观察到的参考

- Wind Alice Market 首页展示能力价值和一段交给 Agent 的接入提示。市场按 MCPs、Skills、Agents 与业务分类检索；详情页包含概览、工具目录、一键配置和按客户端选择的手工配置。个人中心集中提供凭证复制/重新生成和用量记录。来源：[首页与市场](https://aifinmarket.wind.com.cn/#/home)、[公开 Agent 接入入口](https://aifinmarket.wind.com.cn/skill.md)。本轮只读观察，没有安装 Wind 能力或操作第三方密钥。
- MiniMax 的实际“请求管理”页面集中列出 Key 名称、创建时间、最近调用时间和管理操作；其官方快速开始以账号、Key 和调用资源组织步骤。来源：[官方快速开始](https://platform.minimaxi.com/docs/guides/quickstart-preparation)。它仍区分不同计费方式的凭证，不能推断所有产品只有一种 Key。
- DeepSeek 的当前控制台直接提供用量、API keys 和接口文档。MiMo 直接提供个人中心、API Keys、用量及插件入口。仅借鉴入口组织与信息层次，不复制用户的账单、余额、账户标识或第三方密钥。

## 主流程

1. 浏览能力市场：按询价、关务、货物计算、装柜等业务分类查看服务，支持搜索。
2. 查看服务：说明解决什么问题、输入什么、得到什么、支持哪些实际接口，以及当前来源限制。
3. 选择“在线使用”或“接入 Agent”。在线使用只需要经过验证的登录和有效企业权限；Agent 接入使用同一枚 Key 和一段配置指引。
4. 在个人/企业控制台集中管理 API Key、成员和真实调用记录。

能力市场不要求用户先理解 application、client、Grant、audience 或短期 Token。网站不显示没有实现的协议支持；当前 T0 MCP 与其他业务 REST 能力须准确标识。

## 页面结构

主导航：首页、市场、操作手册、个人中心。平台管理员的企业准入和服务授权在管理区保留，不作为普通用户的使用步骤。

能力详情：业务说明、实际工具/API、输入与结果样例、来源与状态、在线使用、一键接入。展示结构保持简洁，工具参数和原始 JSON 按需展开。

个人中心：工作台、API Key、已开通服务、操作记录、成员与账户。普通业务成员默认进入工作台，不展示开发者申请流程。默认接入应用由系统复用或按明确动作创建；高级应用隔离继续可管理，但不要求每个业务员重复填写。

Key 页只有一条常用路径：创建或复用一枚 Key，保存后原位自动验证。现有已交付 Key 原样保留，升级访问范围必须有当前授权、版本检查和审计；不要求用户重复保存同一个秘密。

## 实现与验收界线

统一凭证遵循 `2026-09-06-unified-application-key-v1`。后台继续核对租户、成员、来源、当前授权和撤销状态。上线验收需证明同一 Key 的 T0 与业务调用，而非仅改名隐藏两个输入框。

没有上线计费的服务不画余额或虚构套餐；没有请求时显示真实空态。关务未发布数据、Freightcom 缺少正式企业凭证仍如实显示，不因页面简化变成可用。

操作手册按七章组织：快速上手、账号与服务开通、API Key、REST API、MCP、结果与常见问题、新服务接入。首页指令链接公开 `/console/skill.md`；复制指令不会申请第三方服务或修改客户端配置。
