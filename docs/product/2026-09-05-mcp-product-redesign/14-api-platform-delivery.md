# API 统一平台：实施拆分与验收

[产品规划](11-api-native-platform-prd.md) · [页面规格](12-api-platform-pages.md) · [当前 API 差距](13-api-capability-gap-matrix.md)

状态：产品实施计划，非已完成清单。用户已确认 API 方向、用户管理与申请范围，以及原服务的独立分支改造；不重复请求相同授权。生产部署、真实身份/凭证接入和发布资格仍单独记录证据。

## 1. 先固定三组合同，避免边画页面边猜接口

| 合同切片 | 必须确定 | 兼容与边界 |
| --- | --- | --- |
| 人员与企业 | IdP subject、User/Membership/Invitation、角色、企业归属、人员会话、CSRF、会话撤销、对象权限 | 人员不是 client；客户企业管理员不继承 platform:admin；新客户门户不复用 loopback Admin 暴露方式 |
| 应用申请与授权 | 显式 client 创建、负责人/环境、版本化申请与审核、ServiceGrant/Connection、幂等操作、Key 领取条件、轮换影响 | 保留 credential-exchange v1 三工具；REST/新 MCP 能力用版本化交换合同、audience 和精确操作权限，不允许客户端随意指定 audience/tenant/TTL |
| 业务 API 统一 | 完整关务投影、只读 AI/报价、单项/批量税费、保存/复核/记录、发布身份和恢复接口 | 原加拿大工具兼容；旧 Quote V2 示例不能作为真实费用/币种依据；不修改原规则权威、不默认注册新工具 |

新字段使用闭合 Draft 2020-12 Schema。金额/税率使用 decimal string，单位显式；新对象的审批状态不扩展 MCP 五状态。每一组 RFC 包含旧/新 JSON、权限、迁移、失败恢复、精确测试与回滚，完成基线评审再进入注册与发布实现。

旧 [reuse RFC](../../rfcs/2026-09-05-existing-services-reuse-v1.md) 的只读接口和完整关务投影可作为输入；网页 handoff 不是当前产品主线，改为站内上下文与服务器受权引用。旧通用只读方案也不足以覆盖用户要求的正式保存、人工处理和历史，后者应逐个定义写 API。

## 2. 按能用的闭环推进

### A. 人员与企业

交付：当前身份 provider 接入、客户人员会话、企业准入、首次 owner、成员邀请、角色分配、暂停与移交。新前端路由建议 `/console/`，共享现有视觉与组件；新增目录按平台 RFC 明确所有权，不重写整个 Admin。

完成证据：两个企业、至少业务员/开发者/企业 owner/平台审核员四种主体在同一部署中完成真实角色测试；越权、跨企业、过期邀请与最后 owner 移除均被服务器拒绝；人员无法调用管理或机器换票入口。

### B. API 申请与接入

交付：显式应用创建、API 申请、审核补充、授权写入与读回、负责人领取 Key、REST/MCP 指引与真实调用诊断。先以现有 T0 能力完成最小平台闭环，保留原 T0 行为。

完成证据：申请前无 Key；审核人与申请人分离；审批不返回 secret；授权 active 后应用维护者领取，交付确认后换票；机器完成精确目录和一次已授权计算；吊销、暂停与成员移交后读回正确。

这一步只能叫“企业 API 接入闭环”，不能宣称关务、报价和税费正式版完成。

### C. 第一项业务 API：关务查询

交付：同源工作台表单、追问、候选确认、完整三国结果与来源；新完整投影合同、精确 entitlement 和服务身份/租户映射。API 与 MCP 共用受控应用服务。

完成证据：正常查询、追问、候选复查均通过 M2M；不发送公共 querySessionId；原产国不支持时明确拒绝；status/query 快照变化与 ready=false 保持非成功；网页无业务外跳。

### D. 报价、资料提取与原记录

交付：在报价独立分支中复用原引擎，新增无业务写入的提取和试算路径；补企业/调用方/对象隔离、发布与费用证据；在明确按钮后执行保存或复核；原记录可受权回读。

完成证据：成功/缺项/异常各路径都不误建销售记录、人工任务或发通知；安全访问审计单独保留。新旧同引擎输入的运价结果一致，来源币种不被重标。保存、复核与历史按企业/角色/对象授权；没有原记录恢复能力的路径不能显示保存完成。

### E. 税费单项与批量

交付：把现有 Decimal 核心移到 RiskCustoms 共享领域层；增加受认证 M2M estimate 与有界批量执行、汇率/税则快照核验、行级结果与记录恢复。

完成证据：网页、REST 和 MCP 相同输入/发布证据得到相同金额和复核结果；从量、复合、未确认税率不猜金额；批量部分失败不会变成全成功；状态查询、任务取消语义、重复提交与配额均有明确合同。

### F. 全服务覆盖与上线验收

交付：补齐货物/装柜 REST 映射，知识/状态，原记录/复核，单独推进 Freightcom 正式费率与任何纳入目录的文档服务。每项服务在能力清单中标注“已核验正式/仅测试/待适配”，没有外站替代动作。

正式声明按服务逐项作出；没有成功的生产调用证据时只保留测试或待接入。统一前端可分批上线，但目标“全服务 API 平台”要全部范围验收完成才能结束。

## 3. 可并行工作与所有权

| 工作包 | 主要责任 / 拟写范围 | 依赖 |
| --- | --- | --- |
| 产品与合同 | 根代理/基线；docs/product、docs/rfcs、接受后的 docs/contracts 与 Schema | 本规划、当前三仓代码；保留用户已有更改 |
| 用户与申请域 | Access Gateway 原所有者；services/access-gateway、schemas/access-gateway、对应 tests | 人员/申请合同与 provider 方案 |
| 客户门户与设计系统 | 根代理主导 UI；既有 apps/admin、apps/access-console 与新 console 的窄复用 | 已冻结 API、角色和页面规格；不由后端模型决定页面结构 |
| 关务 | RiskCustoms 独立分支＋MCP adapters/customs 对应所有者 | 完整投影与估算合同、当前源码基线 |
| 报价 | 原报价独立分支＋MCP adapters/quote 对应所有者 | 副作用隔离、tenant 与记录合同 |
| 联调与发布 | 集成所有者；tests/e2e、deploy、docs/runbooks | 上述能力真实通过，获得目标环境配置与发布证据 |

用户已授权独立分支改造。执行时先记录三个仓库 HEAD 和未提交文件；从明确基线创建隔离工作树，不移动、暂存、重置或覆盖用户正在进行的报价工作。原仓库最新工作树差异要逐项确认来源，不能不加区分地复制进新分支。

前端设计由根代理把控，5.6 子代理继续负责接口核查、有明确文件范围的实现与独立审查。API 与页面可以在合同冻结后并行，但不能用 mock 成功代替真实接入；mock 必须标注测试环境。

## 4. 验收用例

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| UI-01 | 询价/关务/估算完整业务旅程 | 浏览器无原业务站跳转、iframe 或携带业务参数的外链；仅请求受控同源 API |
| UI-02 | 桌面1440、手机390、窄屏320/768 | 无页面横向溢出，主按钮可达，键盘与错误焦点正常；输入与结果状态一致 |
| IAM-01 | 邀请过期、撤销、重复、身份不符 | 服务器拒绝，界面可重发/更换身份且不会生成重复成员 |
| IAM-02 | 客户切换 tenant、猜成员/应用/记录 ID | 所有查询/修改/导出拒绝且不泄露其他企业对象存在性 |
| IAM-03 | 暂停成员、移除唯一 owner/应用维护者 | 人员会话按策略失效；先移交或明确暂停，不能留下无负责人应用 |
| IAM-04 | 人员/机器/平台管理员凭证交叉调用 | audience、主体与操作权限均阻断，不把管理账号当业务万能身份 |
| IAM-05 | 浏览器或服务账号伪造原始操作者/企业/角色 | BFF 只从当前会话绑定受认证委托上下文；上游验证并保留人员/应用归属，记录服务身份与原始 actor；验证失败 blocked，不能落成共享管理员记录 |
| APP-01 | 创建应用但未申请 | 有 client ID 和负责人，没有 Key/生产授权 |
| APP-02 | 自审、批准旧申请版本、双击审核 | 拒绝自审/旧版本，幂等处理重复请求，决定可审计读回 |
| APP-03 | 审批通过但授权写入失败或连接未验证 | 分别显示已批准/开通失败/服务待接通，不显示已可用 |
| APP-04 | 仅部分服务批准，或申请的写能力未批准 | grant 与申请差异清楚，Key 和工具目录只含批准子集 |
| APP-05 | grant 暂停、撤销、到期或缩权，旧 Key 仍存在 | 当前 grant 立即约束新 Web 请求与新换票；已签 JWT 按明确撤销/TTL 上界收敛；凭证存在不保留旧权限，撤销授权不自动恢复，续期审核不延长原授权 |
| KEY-01 | 创建、刷新、丢失响应、重复请求 | secret 一次展示；未知结果先读回；不可恢复明文，只能明确吊销重发 |
| KEY-02 | 未交付 Key 换票；已吊销 Key 换票 | 均拒绝；交付不等于接入成功 |
| KEY-03 | 轮换/暂停应用/暂停企业 | 新换票及时拒绝旧身份；已签 JWT 按真实上界收敛，UI 不夸大即时性 |
| API-01 | 未授权 REST 操作、MCP 兄弟工具、错误 audience | 拒绝；旧 T0 v1 不新增工具、权限或意外外部 adapter 构造 |
| API-02 | 缺 IdP/签名/审计/存储 provider | 失败闭合，不用本地 map、SQLite 或测试身份替代生产条件 |
| CUS-01 | 追问、选 HS6、规则日期/快照变化 | 保留原查询上下文、来源和五状态；不发送公共 querySessionId，不误报正式归类 |
| QTE-01 | AI 只提取/试算的成功与异常路径 | 业务表/任务/通知/学习写入均未发生；脱敏访问审计按合同存在 |
| QTE-02 | 原共享 Key 查询其他企业记录 | 原服务和平台均拒绝；仅前端过滤不算通过 |
| QTE-03 | 保存/复核超时后重试 | 同一幂等操作恢复，原系统读回同一记录；不重复通知/建任务 |
| EST-01 | 单项/批量、文本税率、不同币种、失败行 | 同核心与发布证据、decimal string、明确复核/部分失败，不将失败置零 |
| REC-01 | 失效、无权或不支持恢复的来源引用 | 不显示为当前结果；不从 queryId 猜造历史 |
| OPS-01 | 日志、错误、用量和导出 | 无 Key/Token/客户材料正文；用户只能看授权范围，计数来自真实事件 |
| REL-01 | 原版本回滚、关停新能力 | 旧 T0 与原业务工作流仍可按其原权限运行；不删除审计或复活吊销凭证 |

这些是待执行验收，并非已通过。当前这轮只检查产品文档一致性、源码证据定位和文档链接；上一轮 58 项测试不作为新增用户/API 功能的验收。

## 5. 迁移与回滚

1. 先新增合同和域模型，保持旧 client_id、credential 与 T0 交换 v1 可用；应用负责人/环境缺失的旧 client 进入“待认领/待补资料”，不自动猜 owner。
2. 新建客户门户与同源业务入口，不放宽现有 Admin 本地门禁。先以隔离测试环境验证角色与操作；测试企业、凭证、发布和数据不流入正式环境。
3. 原报价服务先补 tenant/对象隔离和只读路径；旧写路径保持明确原语义，不能重定向旧 URL 后暗改副作用。价格和税则继续由原服务管理。
4. RiskCustoms 增加完整投影、共享计算与受权结果记录；从现有浏览器计算迁移时做同输入/版本对比，旧查询接口不冒充新 M2M 合同。
5. 按企业/环境启用新能力，逐项记录 IdP、映射、目录、正式发布与一次调用证据。应用看到其获准范围，不进行默认全量授权。
6. 验收后新版业务主动作全部切换 API；旧外链入口退出产品导航。保留历史代码和验证记录只用于回溯，不作为失败回退到网站的业务路径。
7. 回滚时停用新增授权/版本或回退相应应用构建，保留原数据、申请、凭证元数据与审计。未成功写入不伪造完成，已成功写入不因回滚重复执行。

## 6. 实施前需要收敛的配置，不重复问已确认范围

- 客户准入按“内部员工＋受邀企业客户”默认；用户若选择开放注册，需要追加反滥用与企业归属审核，不能直接开放生产。
- 身份 provider 复用现有企业身份接口；Authentik 草稿需独立核验，不作为已部署事实。具体账号登录方式由当前环境决定。
- 企业配额、正式数据与规则有效期、批量上限、保留期和会话撤销上界来自真实运营/技术合同。规划不捏造价格、容量或 SLA。
- 首期普通轮换按现有立即失效语义；若要求平滑轮换，再接受 successor/有界重叠合同并测试，不仅修改文案。
- 真实生产接入需要目标环境的版本、身份/tenant 映射与发布证据；本轮未连接或部署。

## 7. 本轮产品复核记录
