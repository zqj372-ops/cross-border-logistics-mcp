# FreightClaw 物流能力开放平台

更新：2026-09-07。用户明确指定 JoyAgent 官网（https://joyagent.jd.com/pl/）作为新的视觉参考；延续现有服务市场、操作手册与一把 API Key 的接入方式。本目录交付 `/console/`，原服务适配继续保留；本地新增原生关务与私人地址运价服务，按企业显式绑定，未配置时不回退。

## 信息结构

主导航为首页、市场、CLI、操作手册；个人中心、历史与退出登录收进右上角账号图标。官网与控制台共用服务首页，提供原海运询价、关税查询、税费与尾程工具；CLI 页面提供下载安装、命令选择和输入示例。市场提供业务分类、搜索和 MCP/API 筛选；详情说明输入、结果、实际协议与调用路径，并提供在线使用或系统接入入口。没有上线的计费、余额、Skill 或 Agent 商品不出现在目录中。

个人中心按角色进入：企业所有者、管理员和开发者查看 API Key；普通业务成员直接进入业务工作台；尚未加入企业的用户查看邀请。平台审核和运维保留各自的队列，不使用客户身份。

操作手册提供七章：快速上手、账号与服务开通、API Key、REST API、MCP、结果与常见问题、新服务接入。公开 `/console/skill.md` 让 Agent 读取同一套接入规则；OpenAPI 从实际 Schema 生成。

## 用户与权限

| 身份 | 可完成的工作 |
| --- | --- |
| 业务成员 | 接受邀请，在线使用企业已开放的业务；申请和 Key 深链显示无权限说明 |
| 开发者 | 管理自己负责的应用、申请服务、创建和轮换该应用的 Key |
| 企业管理员 / 所有者 | 企业成员、负责人和授权管理；只有本人负责的应用可以领取 Key |
| 平台审核员 | 审核申请、要求补充、部分批准或拒绝，不能领取客户 Key |
| 平台运维 | 企业准入、核对并开通授权、暂停或撤销，不能冒充客户 |

前端入口与提交动作检查当前企业的有效角色；服务端仍检查当前成员、企业、应用、负责人、授权、凭证和来源状态。

## 简化接入

用户在一个表单选择服务并说明用途。存在一个可管理应用时自动复用，没有应用时在明确提交动作后创建默认应用；存在多个应用时要求选择。后端按实际 T0 与业务合同分别审核，但用户不再填写两份表单。部分提交失败保留操作编号，只重试未完成部分。

服务开通后创建一把 `flcbk_` Key，自动纳入所选应用当前已开通的范围。REST API 直接使用这把 Key；MCP 使用同一把 Key 兑换短期令牌。官网当前部署只有货物计算、装柜规划和 Agent 上下文三个 MCP 工具，五个业务服务通过 REST 提供。2026-09-07 已核对生产运行配置为 `t0-v1`；代码支持的 `business-v1` 八工具模式尚未部署，市场按实际部署展示协议，不能把代码支持写成已上线能力。

已有业务 Key 保持原值。应用负责人可点击“启用基础工具”，在当前 T0 授权、版本检查和审计约束下升级；不会偷偷扩大旧 Key 权限。旧基础工具 Key 深链继续兼容。新增业务服务开通后，可以明确选择“更新服务”，用轮换动作将当前有效业务范围纳入替换 Key，旧 Key 立即撤销。普通轮换不隐式增加权限。

完整 Key 只显示一次。用户确认保存后页面清空明文，自动执行有权限的只读样例，并显示实际处理状态与请求编号。Key 和 Token 不写入浏览器持久存储，切换企业或退出会中止未完成验证。

## 业务状态与验收

申请通过、授权生效、Key 已保存、接口调用与正式数据就绪分别确认。来源返回 `needs_input`、`manual_review`、`blocked` 或 `unavailable` 时保留原状态，不用样例填补；价格试算不等于报价已批准、已发送或可订舱。

本轮浏览器验收覆盖公共市场、搜索分类、实际协议、七章手册、同一 Key 的两类只读调用、明文清空、业务成员深链与 1440/768/390/320 px 布局。截图与拦截结果仅为 UI 证据。当前生产版本、真实身份、来源状态和部署证据以生产交付台账为准。

## 2026-09-07 公开入口调整

货主与商家先选择海运询价或关税查询，首页收短为“询运费，查关税。”，保留原整柜/拼箱需求收集与费用明细服务。海运需求、市场、CLI、手册、关税、税费估算免登录，尾程询价保持登录要求。

未开通企业会话的访客使用站点显式发布的关务连接，关税与税费共用每天 20 次查询，批量按商品数计次。同一网络共享，清缓存不重置，按北京时间零点恢复。页面显示服务端剩余额度；用尽后说明重置时间与个人中心入口，不跳走或删除已填资料。账号数据与写操作保留原权限。

验收：匿名直接深链及查询、20/21 次、批量、重启/跨日、菜单键盘与移动端、尾程和历史未登录拦截、登录后的角色隔离、源数据未就绪原状态返回。

## 2026-09-07 询价受理与进度协作首版

本地已实现客户提交、后台受理和补充资料的同一记录流程。`/inquiry/` 保持公开浏览与填写；保存线上需求使用现有登录账号，登录返回后保留填写内容，也可选择原有邮件草稿方式。提交成功显示需求编号与查看进度入口。账号菜单提供“我的询价”（`#cases`），具备处理权限时提供“询价管理”（`#operations`）；双方通过 `#case/UUID` 读取同一条需求的详情。

客户查看自己的需求和公开进展，在需要补充时回复。处理人员按权限筛选待处理、处理中、待补充、已结束或已取消，填写客户可见进展及可选内部备注；内部备注由服务端过滤。保存后读回记录，打开或刷新页面读取最新状态；首版没有实时推送或邮件提醒。结束询价仍不表示报价确认、订舱或发运。后台延续现有前台视觉体系，手机先呈现操作与进展，再展示需求资料。

此首版尚未在生产启用，默认关闭，当前仅支持单实例 SQLite。关务与私人地址运价引擎、配置发布现已在本地实现，详见下节；报价导出、文件中心、OCR / SO 识别和邮件订舱继续按后续阶段推进。本地隔离合成验收与实际启用状态分别记录；详细流程、截图、复现命令与后续顺序见 [第一阶段交付](../../docs/product/2026-09-07-business-cases-delivery.md)，权限及状态迁移见 [询价受理 RFC](../../docs/rfcs/2026-09-07-portal-business-cases-v1.md)。

## 2026-09-07 原生关务与私人地址询价

业务管理新增关务数据、私人地址运价、Freightcom 连接三项，延续现有前台视觉。当前企业与发布状态置于表单前；草稿 → 来源核验与预览 → 明确确认发布，支持停用与历史回退。网页与 CLI 使用同一业务服务和发布版本。配置从空白开始，不导入旧运价或旧凭证。

自有运价使用移植的 Decimal / Python 计费逻辑，支持完整邮编优先、分区、计费托数、住宅费、尾板、地牛、预约和等待费；结果直接显示来源、发布版本和有效期。未覆盖、缺档或过期时不会补价。Freightcom 独立维护加密凭证，私人地址请求明确住宅收货、卸货和预约条件；保存凭证不代表实时报价验证通过。

原生关务保留完整查询合同的税号、税率、贸易措施、单证、来源和发布标识；支持税费单笔/批量估算与个人历史。只接受经业务核验的规范化数据包；测试标记、来源不足或变更中断均阻止成功结果。

本地隔离验收覆盖配置、预览、发布、草稿隔离、查询、停用、回退及网页/CLI 一致性，并检查 1440 与 390 px 布局。合成测试不能证明正式关务数据、正式运价或 Freightcom 账号已就绪；三项正式配置仍为空。本轮没有部署生产，原生后台目前仅支持单实例 SQLite。
