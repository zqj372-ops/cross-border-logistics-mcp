# Access Console

这是 Unified Access Gateway 的窄前端资产。它不是通用后台，也不扩大 MCP 权限边界；页面只管理
租户、调用方、长期 Key 和三个镜像内置 T0 工具权限，并展示固定五个 Agent 标准资源的认证验收。

## 产品操作模型

页面以“一个租户、一个当前动作”为主线，按以下四步推进：

1. 创建或恢复租户；
2. 为调用方签发一次性长期 Key，并选择完整 T0 权限集合；
3. 把完整 Key 保存到批准的 Secret Manager，确认交付；
4. 用长期 Key 兑换短期 JWT，实际调用 3 tools、读取 5 resources 后给出脱敏验收结果。

“接入任务台”只根据服务端状态和精确读回计算下一步，不以按钮点击、HTTP 200 或页面提示推断完成。
Agent 接入清单只包含 endpoint、环境变量名和精确目录预期，不包含 Key/JWT，也不是可直接导入的
凭证配置。

## 写操作完成条件

每次写操作必须同时满足以下条件才在 UI 中显示为完成：

- 服务端返回 `operation_id`；
- 从 `/admin/api/v1/access/state` 读回同一 `operation_id`；
- operation 的 `status=success` 且 action 与本次动作一致；
- 目标租户、调用方或凭证状态与预期一致；
- 凭证签发、轮换、吊销和交付确认还要读回同一 credential 与完整工具集合。

暂停租户、停用调用方、吊销与轮换 Key 必须先显示影响范围并由操作者确认。轮换默认继承被轮换
凭证的权限，而不是读取另一张签发表单的临时勾选。写入期间页面锁住其他写入口，避免并发误操作。

## 一次性 Key 安全规则

- 完整 Key 只保存在当前页面内存，不写入 URL、Cookie、浏览器存储或结果记录；
- “已复制”不等于“已安全交付”，必须明确确认已保存到外部安全凭证位置；
- 可选择“确认交付并立即验收”，形成签发、交付、兑换和 MCP 读回的连续闭环；
- 如果待交付 Key 已离开当前页面且完整值丢失，页面不允许直接确认，只能吊销后重新签发；
- 页面仍持有未处理的一次性 Key 时，离开页面会触发浏览器警告。

## 边界与资格

当前仓库提供前端合同、本地合成测试、受管理员保护的状态/overview API 与失败闭合写入流程。
生产资格仍必须由目标环境的企业 IdP、TLS、KMS/Secret Manager、托管数据库、限流、审计、集中
吊销、备份恢复、负载、告警和回滚演练共同证明；前端健康或认证验收通过均不能单独授予生产资格。
